# TwinVM Stage 4.2 修复报告（第七轮：探针破案 —— DEX2OATBOOTCLASSPATH 必须是 BOOTCLASSPATH 的真前缀）v0.7.38 → v0.7.39

> 日志我自己取的：`/sdcard/Android/data/dev.twinbox.vm/files/twinvm-20261014-065541.log`（v0.7.38 的探针版，ROM 63 inodes）。

## 1. 探针给出了决定性答案（v0.7.38 埋的 `/bin/probe`）

探针是**动态 PIE**（与 dalvikvm 同一条装载路径），它的输出直接从 guest stdout 落进了日志：

```
[probe] argc=4 argv: [dalvikvm] [-cp] [/rom/hello.dex] [Hello]
[probe] environ 条数=9
[probe]   BOOTCLASSPATH=/apex/com.android.art/javalib/core-oj.jar:…:apache-xml.jar
[probe]   DEX2OATBOOTCLASSPATH=/apex/com.android.art/javalib/core-oj.jar:…:apache-xml.jar
[probe]   ANDROID_ROOT=/system
[probe]   ANDROID_DATA=/data
[probe] 关键路径 open 结果（fd≥10000 = ROM 虚拟 fd）：
[probe]   /apex/com.android.art/javalib/core-oj.jar          -> fd=10000
[probe]   /apex/com.android.art/javalib/boot.art             -> fd=10000
[probe]   /system/framework/arm64/boot.art                   -> fd=10000
[probe]   /system/lib64/libart.so                            -> fd=10000
[probe]   /system/bin/dalvikvm                               -> fd=10000        （11 个路径全部命中）
```

**结论一：环境完整地进了动态映像**（9 条，关键 4 条都在）——上一轮"环境没到"的假设被排除。
**结论二：ROM 布局全部正确**（jar / boot 镜像 / 库路径都能开）。

## 2. 报错文案变了 → 真凶浮出来

```
v0.7.37：file_utils.cc:609 Check failed: !location.empty() BOOTCLASSPATH and DEX2OATBOOTCLASSPATH must not be empty
v0.7.38：file_utils.cc:609 Check failed: !location.empty() No mainline framework library found   ← 新
```

反汇编 `libartbase.so` 的 `art::GetFirstMainlineFrameworkLibraryFilename()`：它读 **BOOTCLASSPATH**
与 **DEX2OATBOOTCLASSPATH** 两个 env，并遵守 libartbase 里已有的那句约束：

```
DEX2OATBOOTCLASSPATH must be a prefix of BOOTCLASSPATH
```

**前缀之后剩下的那些 jar = ART 眼里的 mainline framework library**；如果两者完全一样（前缀后为空），
它找不到 mainline → `No mainline framework library found` → FATAL。

**而把两者设成一样，正是我上一轮自己引入的错**（我在 `guest_stage42.c` 里给
DEX2OATBOOTCLASSPATH 抄了整条 boot classpath）。真机约定是：

| 变量 | 真机值 |
|---|---|
| `DEX2OATBOOTCLASSPATH` | `…/core-oj.jar:…/core-libart.jar`（只两个） |
| `BOOTCLASSPATH` | `…/core-oj.jar:…/core-libart.jar:…/okhttp.jar:…/bouncycastle.jar:…/apache-xml.jar` |

（与设备 `/apex/com.android.art/etc/classpaths/bootclasspath.pb` 完全一致。）

## 3. 本轮修复

1. **`core/guest/guest_stage42.c`**：`DEX2OATBOOTCLASSPATH` 改成**真前缀**（core-oj + core-libart），
   `BOOTCLASSPATH` 保持 5 条 → 前缀之后 = okhttp/bouncycastle/apache-xml，即 mainline 部分。
2. **ROM 补 `/linkerconfig/ld.config.txt`**（内容与已有的 `/system/etc/ld.config.txt` 一致）——
   消掉 guest linker 那句 `failed to find generated linker configuration` warning，namespace 行为更贴近真机。
3. **修一个我自己的构建疏漏**：上一版我把启动镜像只塞进了「当时的 ROM」，没进 fixture →
   这次 `tools/build_android_here.sh` 重打 ROM 时它就丢了。现在已写进
   `rom/fixture/android_root/system/framework/arm64/`，以后每次构建都在。
4. 版本 0.7.38 → **0.7.39**（versionCode 61 → 62）。

ROM 现状：**65 inode / 53.3 MB**，`checkrom --strict` PASS；`/apex/com.android.art/javalib/*.jar`(6)、
`etc/classpaths/*.pb`(2)、`boot.{art,oat,vdex}`（`/apex/.../javalib/` 与 `/system/framework/arm64/` 两处）、
`/linkerconfig/ld.config.txt`、`/bin/{guest,probe}` 齐备。
