# TwinVM Stage 4.2 修复报告（第十五轮：闪退是我自己引入的栈越界 —— 已修）v0.7.46 → v0.7.47

> 现场：`twinvm-live.log`（381KB，TRAP 打到 **4096**，黑匣子出了一行 `child wchan: 0`）
> ＋ **tombstone_31**（`/data/tombstones/`，2026-10-14 08:11）。App 是**闪退**，不是卡死。

## 1. tombstone 直接指认凶手

```
signal 11 (SIGSEGV), code 2 (SEGV_ACCERR), fault addr 0x00000070f226fd67
pid: 7732, tid: 22593, name: twinvm-selftest
      #00 pc ... bionic/libc.so (__memmove_aarch64_nt+168)
      #01 pc ... lib/arm64/libtwinvm.so (Java_dev_twinbox_vm_Native_stage0+1616)   ← 我上一轮加的黑匣子
      #02 pc ... libart.so (art_quick_generic_jni_trampoline+144)
      #03 ... MainActivity$1.run
```

**根因（我的 bug）**：黑匣子那段代码里我声明了局部 `char pp[64], buf[512];` ——
**`buf` 遮蔽了外层那个"控制台收集缓冲" `buf`**。于是后面那句

```c
if (len + n2 < cap) { memcpy(buf + len, out, n2); len += n2; }
```

本想追加到控制台缓冲（`len` 当时约 38 万），结果写进了那个 **512 字节的栈数组** → 越界 →
`__memmove` 段错误 → 整个 App 闪退。

（补一句：`len + n2 < cap` 这个界检查本身没错，错的是**被写的对象变了**。这就是典型的变量遮蔽。）

## 2. 修复（v0.7.47）

1. 黑匣子的本地读缓冲改名为 **`pbuf`**（三处 `/proc/<pid>/{syscall,wchan,status}` 读取全部改），
   追加到控制台缓冲的那三条 `memcpy(buf + len, ...)` 保持原样（现在指向正确的对象）；
2. **构建脚本加 `-Wall -Wshadow`**：以后这种"局部遮蔽外层缓冲"在**编译期**就会报出来，
   不会再走到真机上变成闪退。
