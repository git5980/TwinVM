# TwinVM Stage 4.2 修复报告（第十九轮：黑匣子定位到"放行即被杀"，探针改为全量审计）v0.7.50 → v0.7.51

> 现场：`twinvm-20261014-083744.log`（92KB）。

## 1. 共享黑匣子成功工作，并给出决定性结论

```
[TwinVM] [bb] 子进程最后的 syscall（seq=150003，最新在后）:
[TwinVM] [bb]   nr=227  a0=0x687ff000  pc=0x70e8530a4c      ← msync 逐页 flush（大量）
[TwinVM] [bb]   nr=174  a0=0x0         pc=0x70e8530d8c      ← getuid
[TwinVM] [bb]   nr=66   a0=0x63        pc=0x70e85303cc      ← writev(fd 99, 日志)
[TwinVM] [bb]   nr=163  a0=0x3         pc=0x70e85311cc      ← getrlimit
[TwinVM] [bb]   nr=56   a0=0xffffff9c  pc=0x70e853178c      ← openat(AT_FDCWD, …)  即 stat/maps
[TwinVM] [bb]   nr=80   a0=0x274c      pc=0x70e85306cc      ← fstat(合成 fd)
[TwinVM] [bb]   nr=63   a0=0x274c      ...                  ← read
[TwinVM] [bb]   nr=57   a0=0x274c      ...                  ← close
[TwinVM] [bb]   nr=56 / 80 / 63 / 63 / 57                    ← 第二次（maps）
[TwinVM] [bb]   nr=57   a0=0x274c      pc=0x0               ← 最后一条：close
```

**关键推理**：整个引擎对**每一个 TRAP** 都会写黑匣子。黑匣子里**最后一条是 `close`**，
之后什么都没有 —— 说明那次致命 syscall **根本没有 TRAP**：

* 它被**我们的 BPF 放行**（放行 = 原生执行 = 不经过引擎 = 黑匣子看不到）；
* 随后被 **App 策略 `SECCOMP_RET_KILL_PROCESS` 直接杀**（无 handler、无 TRAP 行、`code=-31`）。

也就是说：**"放行清单"里至少还有一条 syscall 是 App 策略要杀的** ——
v0.7.48 的策略探针只猜了 29 个名字（命中 11 个），没覆盖全。

## 2. 本轮修复（v0.7.51）：探针改为"全量放行清单审计"

1. JNI 直接 `#include "bpf_gen.h"`，拿**真实的放行清单**（arm64 40 条，每条都带名字）
   逐条 fork 子进程实测：只把 **SIGSYS(31)** 记为"App 策略 KILL"，
   其它信号（比如 `rt_sigreturn` 自己会 SIGSEGV）记为"非 KILL"，避免误判；
2. 之前实测出的 11 条 KILL 名单保留为对照；
3. 顺带修掉生成器的一个坑：`VM_BPF_ALLOW_NRS_COUNT` 原来写在架构分支**外面**，
   arm64 会拿到 x86_64 的 42 —— 探针按它遍历就会**越界读**。
   现在两份表各自定义条数（42/42、40/40，已校验一致）。

## 4. 下一轮（就是收口了）

装 v0.7.51 → 点「运行」。日志开头会列出**放行清单里每一条**的实测结果，形如：

```
[TwinVM] [policy] 审计放行清单（40 条）：逐条 fork 子进程实测
[TwinVM] [policy]    futex(98) -> 安全
[TwinVM] [policy] !! xxxx(N) -> SIGSYS — App 策略 KILL！必须从放行清单摘掉
[TwinVM] [policy] 放行清单里有 K 条会被 App 策略 KILL
```

拿到 `K` 条名字后：**逐条从 `gen_bpf.py` 的 ALWAYS 里摘掉**（能伪造的在引擎里伪造，
不能的让引擎回 `-ENOSYS`，bionic/ART 一般都有退化路径 —— `rseq` 就是这么过去的），
再重新生成、重编、出包。到那时放行清单就与 App 策略**无交集**，"无痕 SIGSYS"这类故障会彻底消失。
