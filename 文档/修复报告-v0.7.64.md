（帧名与实际代码有偏差——unwinder 用我们 maps 里的基址做符号化，guest 的
实际加载基址与宿主记录有偏差；**pc 偏移量是准的**：abort 位置 =
libart+0x80caf4。）

guest 仍走到 ClassLinker 全部完成后 abort（code=127）——与 v0.7.62 同点。

## 2. 示踪器 0 事件终审：GSI 结构体大小陷阱

0x80 停点判断已修（v0.7.63），但依然 0 事件。字节级验证 .so 确含
`cmp #0x85` 指令后，唯一剩下的失败点：**PTRACE_GET_SYSCALL_INFO 的 len 参数**。

内核 `struct ptrace_syscall_info` = **88 字节**（union 最大成员 seccomp 分支
= nr(8) + args(6×8) + ret_data(8) = 64）。我们只声明了 entry 分支（56）→
传 len=80 < 88 → **内核直接 EINVAL，每次 GSI 都失败**——静默（r=-1 不记录，
PTRACE_SYSCALL 照常续跑），于是"一切正常"却 0 事件。

## 3. v0.7.64 修复

`struct tvm_psi` 的 union 补全到最大分支（seccomp=64B）→ sizeof=88 与内核
一致；字段访问改为 `info.u.entry.*`。
