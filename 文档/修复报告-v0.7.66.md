# TwinVM 修复报告（第十七轮：示踪器全面开工 + abort 原因行出水）v0.7.65 → v0.7.66

## 1. v0.7.65 真机判读：示踪器全面开工（336,248 个事件！）

ptrace 三件套集齐（追踪者线程本人 wait + 0x80 掩码 + TRACESYSGOOD），完整
syscall 流水落地。两个关键读数：

1. **死前最后 syscall：nr=94 exit_group(0x7f)** —— 127 = ART abort 后的
   自杀收尾（与 code=127 吻合，证据链闭合）；
2. **abort 前的现场**：82,106 次 madvise(215)（CMC GC 的页回收循环——
   正常 GC 行为）→ #336167 起 process_vm_readv(270) 取证 + write(5) 写
   logd socket → abort dump。

## 2. abort 原因行出水的最后一公里

trace 显示：`#336176 nr=64 a0=0x5`（write，fd=5）——**logd socket 上的
write 藏着 abort 的原因行**，但 BPF 对真 fd 原生放行 → 内容进了内核
socket → 我们看不见。这就是"裸 abort"之谜的最终答案：
**不是没打印，是打印进了我们看不到的管道。**

（旁证：abort dump 的碎片文本散落在 trace 行之间——它们走 writev(fd83)，
而原因行走 write(fd5)，两条管道。）

## 3. v0.7.66 修复：write 真 fd 全部 tee

| 层 | 改动 |
|---|---|
| **BPF** | write 的 3..9999 从 ALLOW 改 **TRAP**（console 由安装期 CONSOLE 补丁特判 ALLOW——引擎宿主侧写不受影响） |
| **handler** | 真 fd 的 write → tee 到 console + 假装写满（v0.7.19 writev 同款先例；不直发=无二次 TRAP） |
| **生成器 bug** | JGT 标签硬编码 ALLOW 的特判修复（ins[3] 指定目标）——之前改了标签被静默覆盖 |
| **bpf_sim** | write(fd=5) 断言改为期望 TRAP（新语义） |
