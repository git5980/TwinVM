## 2. tombstone 一锤定音

```
signal 31 (SIGSYS), code 1 (SYS_SECCOMP), fault addr --------
Cause: seccomp prevented call to disallowed arm64 system call 313
```

**arm64 syscall 313 = `sched_setattr`**（libc 内嵌策略文本里也能看到这个名字）。

而我们的过滤器对 313 是什么态度？**离线模拟器实测 = TRAP**（不是放行）。
所以杀它的**不是我们的过滤器**，而是**更外层的 Android zygote seccomp 策略**
（编译进 libc.so 的那套 filter，App 进程一出生就挂着，早于我们的 VM）。

结论：**ART 在 `StartupCompletedTask` 里调用 `sched_setattr`（313）→ 被 zygote 策略
KILL_PROCESS 直接杀（绕过一切 handler）→ ART 的 Abort/exit_group(0x7f) 收尾**
（★ 死前最后 syscall `nr=94 exit_group(0x7f)=127` 与 `code=127` 完全吻合，证据链闭合）。

**这类 syscall 我们拦不住**（过滤权不在我们手里），只能：
① 提前探明名单；② 在 ROM/引擎层把调用点绕开（例如让 ART 以为不支持、
或替换掉触发它的那段逻辑）。

```

```

拿到名单后，我会按"**能绕的绕、能假的假**"处理：

* 若真正触发的是 `sched_setattr`：在引擎里**不让它落到原生**（我们 BPF 已 TRAP，
  但 zygote 层在更外层 —— 所以要在 **ROM 侧**解决：ART 调用它是因为
  `SetTaskProfiles`/`sched_setattr` 路径被启用，可用属性/环境把它关掉，或让
  相关 syscall 在 guest 侧拿到 ENOSYS 后自然退化）；
* 其余命中项同理，全部走"提前探明 → 绕开调用点"。
