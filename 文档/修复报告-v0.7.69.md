# TwinVM 修复报告（第二十轮：探针彻底移出 App 进程族）v0.7.68 → v0.7.69

> 现场：`twinvm-20261014-185537.log` + `tombstone_31`（18:54:30）

## 1. v0.7.68 之后：**又是我的探针，又是连坐**

```
Cause: seccomp prevented call to disallowed arm64 system call 320
  #00 libtwinvm.so (Java_dev_twinbox_vm_Native_stage0+5352)
  #03 dev.twinbox.vm.MainActivity$1.run+86
```

上一轮我把探针从"父进程"挪到了"槽位子进程"，**但没用** —— 因为槽位子进程同样是从
App **fork** 出来的，而 `SECCOMP_RET_KILL_PROCESS` 杀的是**整个进程（线程组）**，
fork 出的子进程照样连坐。于是：

* v0.7.67 崩在 `syscall 306`（`io_pgetevents`）
* v0.7.68 崩在 `syscall 320`
* 两轮的 "code=127 / Runtime aborting" **都是探针自杀**，不是 ART 的问题

（提醒：`kZygoteBlocked` 里我误写了 `sched_setattr = 274`（x86 号）与 313 的混淆，
但实测 `274` 是**安全**的 —— 这条不影响结论；真正要修的是**探针的宿主**。）

## 2. v0.7.69：探针改成**独立可执行文件**

1. 新增 `core/guest/guest_probe_policy.c` → 编译成静态 `probe_policy`，**打进 ROM**
   （`/bin/probe_policy`）；
2. App 侧：从 ROM 里**解出**该文件到 `/data/local/tmp/tvm_probe_<pid>`（chmod 0700），
   再 `fork + execv` 启一个**与 App 无亲缘依赖的独立进程**去逐条试调；
3. 结果经**管道**回传（`nr sig` 每行一条），写 logcat 与 live 日志；
4. 独立进程死了**与 App 无关** —— 这正是前两轮缺的那一环；
5. 顺带修正：探针只在 ROM 里存在该程序时才跑，缺了就打印一行跳过说明。

## 3. 验证

* `make -C core test` 5 项全绿；`checkrom --strict` PASS；
* **ROM md5 未变**（本轮只动引擎；`probe_policy` 会随下次重打 ROM 进包）；
* APK `versionCode=92 / versionName=0.7.69`，同源签名；
* APK 内 `libtwinvm.so` 确认含 `probe_policy` 路径串（3 处）。

## 4. 下一轮怎么读

装 v0.7.69 → 点「运行」，日志里会出现：

```
[TwinVM] [policy] 用独立进程探针：/data/local/tmp/tvm_probe_12345
[TwinVM] [policy] 独立进程结果: 282 0          ← 号 + 信号（0=安全，31=被拦）
[TwinVM] [policy] 独立进程结果: 306 31
[TwinVM] [policy] 探针进程退出：0
```

**关键**：这次 App 不会再被探针带走，所以同一个 run 里就能同时拿到
①zygote 拦截名单（哪些 syscall 一碰即死）②ART 的真实 abort 现场 —— 两条线终于能分开看。
