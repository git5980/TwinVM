# TwinVM 修复报告（第二十一轮：内嵌独立探针 —— 不再依赖重打 ROM）v0.7.69 → v0.7.70

> 现场：`twinvm-20261014-190306.log`（v0.7.69）

## 1. v0.7.69 的结果：探针**没跑起来**（但 App 也没再被自杀）

```
[TwinVM] guest 槽位启动 pid=15422：ROM 67 inodes 就绪
... （没有一行 [policy] 输出）...
runtime.cc:719] Runtime aborting...
native: #00 art::StartupCompletedTask::Run+272
guest 槽位退出: code=127
```

检查代码定位到原因：**`/bin/probe_policy` 不在 ROM 里**。
因为 ROM 是**沿用的固定基线**（`md5 fa88cc28`，本轮只换 `.so`），而 v0.7.69 的探针
是"打进 ROM 再解出来执行"的方案 —— 基线没重打，自然找不到，于是静默跳过。

**好消息**：App 这次**没有**被探针带走（tombstone 不再指向 `libtwinvm.so`），
说明"独立进程"的思路是对的，只是交付路径没通。

## 2. v0.7.70：探针**内嵌进 .so**，与 ROM 解耦

1. 把探针重写成**无 libc 版本**（`core/guest/guest_probe_policy.c`）：
   只用原始 `svc`（`clone/wait4/write/exit_group`），自带 `memcpy/memset`，
   `naked _start` 取初始 `sp` 拿 argc/argv —— **体积从 3.4 MB 降到 3248 字节**；
2. `tools/gen_probe_blob.py` 把它转成 C 数组头 `android/jni/probe_policy_blob.h`，
   **编译进 `libtwinvm.so`**；
3. App 启动时把这段字节**落盘**到 `/data/local/tmp/tvm_probe_<pid>`（chmod 0700），
   再 `fork + execv` 起独立进程，结果经管道回传 → 写 logcat + live 日志；
4. 于是：**改探针只需要重编 `.so`，完全不用动 ROM**（ROM 继续保持固定基线）。

## 3. 验证

* `make -C core test` 5 项全绿；`checkrom --strict` PASS；**ROM md5 未变**；
* APK `versionCode=93 / versionName=0.7.70`，同源签名；
* `.so` 体积只从 83,216 → 83,216 B 级别（blob 仅 3.2 KB）；
* 探针二进制为 arm64 `ET_EXEC`、entry 0x201264、3248 字节。

## 4. 下一轮预期输出

装 v0.7.70 → 点「运行」，日志开头应出现：

```
[TwinVM] [policy] 用独立进程探针：/data/local/tmp/tvm_probe_12345
[TwinVM] [policy] 独立进程结果: 98 0        ← syscall 号 + 信号（0=安全，31=被拦）
[TwinVM] [policy] 独立进程结果: 306 31
[TwinVM] [policy] 探针进程退出：0
```

这次探针**一定会跑**（不再依赖 ROM），而且它死了与 App 无关 ——
同一个 run 里能同时拿到 ①zygote 拦截名单 ②ART 真实 abort 现场。
