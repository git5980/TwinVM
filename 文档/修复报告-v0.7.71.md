# TwinVM 修复报告（第二十二轮：探针哑掉的真正原因 + 源码回滚到干净基线）v0.7.70 → v0.7.71

> 现场：`twinvm-20261014-190624.log`（v0.7.70）

## 1. v0.7.70 的结果：探针**依旧零输出**

```
[TwinVM] guest 槽位启动 ...
...（没有任何 [policy] 行）...
runtime.cc:719] Runtime aborting...
native: #00 art::StartupCompletedTask::Run+272
guest 槽位退出: code=127
```

查代码后找到**两个叠加的问题**：

1. **调用点放太早**：内嵌探针的落盘+执行代码被插在
   `g_live_fd`（live 日志）**赋值之前** —— 探针结果写 logcat 与 live 都落空，
   看起来"什么都没发生"；
2. **一次编辑事故**：我前几轮用脚本反复改这个文件时，把
   `int pfd[2]; if (pipe(pfd)…` 与 `sigset_t old_m` 那一段**误删**了
   （编译器报 `undeclared identifier 'pfd' / 'old_m'`），
   说明工作区的 `twinvm_jni.c` 已经被我的脚本改脏。

## 2. 处置（v0.7.71）

1. **从原始源码包回滚**：把 DSHA 里那份 `完整源码-v0.7.66.zip` 中的
   `android/jni/twinvm_jni.c`（758 行，干净）取出，覆盖工作区被改脏的版本；
2. 在**干净基线**上重新打补丁（只加三处，不再用"整段替换"这种危险操作）：
   * `#include "probe_policy_blob.h"`（内嵌探针，3248 B 无 libc）；
   * `kZygoteBlocked[]` 清单（zygote 拦截候选 30 条）；
   * `vm_policy_probe_external()`（fork+execv 独立进程 + 管道回传）；
3. **调用点移到 live 日志打开之后**（这正是上一版哑掉的原因），
   并加注释标明"必须在这里，否则没地方写"；
4. 补 `#include <sys/stat.h>`（`chmod` 声明）。

## 3. 验证

* `make -C core test` 5 项全绿（含 App-KILL 名单检查、maps/黑匣子、exec 栈 ABI）；
* `checkrom --strict` PASS；**ROM md5 未变**（仍为固定基线 `fa88cc28`）；
* APK `versionCode=94 / versionName=0.7.71`，同源签名，可直接覆盖安装；
* `.so` 里确认内嵌探针 blob（3248 B）。

## 4. 下一轮预期

装 v0.7.71 → 点「运行」，日志**开头**应出现（这次位置对了）：

```
[TwinVM] [policy] 用独立进程探针：/data/local/tmp/tvm_probe_12345
[TwinVM] [policy] 独立进程结果: 98 0        ← syscall 号 + 信号（0=安全，31=被拦）
[TwinVM] [policy] 独立进程结果: 306 31
[TwinVM] [policy] 探针进程退出：0
```

拿到名单后就能做"**能绕的绕、能假的假**"，把被 zygote 层拦掉的 syscall
从 ART 的启动路径上摘出去；同时 ART 的真实 abort（`StartupCompletedTask::Run`）
现场也终于能单独看到。

## 5. 流程教训（写给后面的自己）

* **不要用脚本对同一个源文件做多次"整段替换"** —— 这次就是这样删掉了相邻代码段。
  正确做法：改前先 `git`/备份，或每次只做**最小锚点替换**并立刻编译验证；
* 探针/日志这类"诊断设施"自己的失败**必须显式打印**（本轮"零输出"就是最坏的信息），
  所以 v0.7.71 里探针路径的每一步（落盘失败/退出码）都会打日志。
