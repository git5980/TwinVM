# TwinVM 修复报告（第三十二轮：★★★ 真凶 —— guest 自己安装了 seccomp 过滤器）v0.7.81 → v0.7.82

> 现场：`twinvm-live.log`（8.5 KB，v0.7.81）

## 1. 裸 write 探针给出"零输出"，反而锁定了方向

v0.7.81 的 `[HR]` 裸探针（不依赖 libc/TLS/格式化）**一条都没打**；
连 `TRAP#1`/`HND#1` 都消失了，**黑匣子 `seq=0`**（一个 syscall 都没进引擎）。

**这三个"零"合起来只有一个解释**：过滤器装好之后，**我们的 handler 从来没被调用过**。

## 2. 逐条读 trace，凶手现形

```
#18  nr=132  sigaltstack(…)
#19  nr=134  rt_sigaction(0x1f=SIGSYS, …)      ← bionic 自己设了 SIGSYS 处置
#20  nr=167  prctl(a0=0x26 = 38 = PR_SET_NO_NEW_PRIVS, a1=1)
#21  nr=167  prctl(a0=0x16 = 22 = PR_SET_SECCOMP, a1=2 /*SECCOMP_MODE_FILTER*/, a2=&fprog)
#22  nr=64   write(5, …, 0x5a)
#23..#26 （getpid/mmap/set_tid_address/faccessat）
#27  nr=0    ← 不是真 syscall：进程已死，示踪器读到的是**退出码**
```

**关键**：`#20/#21` 是 **guest（bionic）自己安装 seccomp 过滤器**！
而我们的 `prctl` 处理是**无条件透传**：

```c
case VM_NR_prctl: return VM_PT5(VM_NR_prctl, a0, a1, a2, a3, 0);
```

于是 guest 的策略装上了（Android 的 zygote policy，**KILL_PROCESS** 语义）。
内核里 seccomp 过滤器**后装的那层排在前面**，我们这层被"盖住"了 ——
**此后 guest 的每一个 TRAP 都按它那层处理 → 第一条就 KILL_PROCESS → 进程秒死**，
我们的 handler 永远进不去。

**这一条解释了全部现象**：
* `HND#`/`TRAP#`/`[HR]` 全零（handler 从未被调用）；
* 黑匣子 `seq=0`（没有任何 syscall 进引擎）；
* "死前最后 syscall" 忽而是 `270`、忽而是 `0`（后者是示踪器把退出码当成了号）；
* 之前 v0.7.55~66 那些"ART abort 无原因行"，与这次是**同一类**问题的一部分。

## 3. v0.7.82 修复

```c
case VM_NR_prctl: {
    /* guest 想装自己的 seccomp → 假装成功，绝不透传（过滤器只由我们这一层掌控） */
    if ((long)a0 == 38 /*PR_SET_NO_NEW_PRIVS*/ ||
        (long)a0 == 22 /*PR_SET_SECCOMP*/) return 0;
    return VM_PT5(VM_NR_prctl, a0, a1, a2, a3, 0);   /* 其余 prctl 照旧透传 */
}
```

选"假装成功"而不是"返回错误"：bionic 不校验返回值的语义，若回 `-EPERM`
它可能直接 `__android_log_assert` 中止；返回 0 则它会以为装好了，继续往下走。

## 4. 验证

* `make -C core test` 5/5 PASS；`checkrom --strict` PASS；ROM md5 未变；
* APK `versionCode=105 / versionName=0.7.82`，同源签名。

## 5. 下一轮预期

装 v0.7.82 → 点「运行」。这次应能看到：

```
[TwinVM] [4.2dbg] HND#1 nr=48 …     ← 我们的 handler 重新开始被调用
[TwinVM] [4.2dbg] HND#2 nr=…  HND#3 nr=…
[TwinVM] [HR] nr=…                  ← 裸探针留痕
```

久违的 syscall 流水（TRAP 编号持续增长）应该回来了 —— 这是把 ART 启动继续往下推的
**关键一步**。（若仍无 `HND#`，下一步就检查 guest 是否用 `clone(CLONE_NEWUSER|…)`
或其它路径绕过 `prctl` 装过滤器。）
