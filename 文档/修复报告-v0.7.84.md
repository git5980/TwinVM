# TwinVM 修复报告（第三十四轮：★★★ 总根源 —— 装载阶段没有过滤器）v0.7.83 → v0.7.84

> 现场：`twinvm-live.log`（8.4 KB，v0.7.83）

## 1. v0.7.83 修了 prctl，症状却分毫未动

`HND#`=0、`[HR]`=0，`#20/#21` 的 `prctl` 照旧执行，死前仍是 `nr=0`。
先用三条硬证据排除"构建/安装"层面的问题：

| 检查 | 结果 |
|---|---|
| `gen_bpf.py` 里 prctl 是否已摘 | 已摘（arm64 段无 prctl；仅 x86 段注释文字残留） |
| APK 内 `.so` 与构建产物 | `cmp` 一致 |
| **设备已安装 APK** 里的 `.so` | md5 `0fdadf70…` **与我的构建完全一致** |
| 离线 BPF 判决 | `nr=167(prctl) -> TRAP` |

**离线判 TRAP、真机却不 TRAP** —— 于是去比对"过滤器安装点"与"prctl"在日志里的**先后**：

```
日志第 90/91 行:  [trace] #20/#21  nr=167 prctl(38) / prctl(22, FILTER, &fprog)
日志第 93 行:     [TwinVM] 拦截就绪，装载 guest entry=0x221e80…
```

**`prctl` 发生在"拦截就绪"之前 —— 那时我们的过滤器还没装上！**

## 2. 总根源：`vm_loader_prepare()` 会执行 guest 代码

```c
VmLaunch launch;
int r = vm_loader_prepare(g->map, g->size, &launch);   // ← 它自己跑 guest 的 ELF 解释器！
...
int sr = vm_sigsys_install(console_fd);                // ← 过滤器在这里才装
```

**装载阶段完全在过滤器之外**。于是 guest 的 linker 在装载期就用
`prctl(PR_SET_NO_NEW_PRIVS)` + `prctl(PR_SET_SECCOMP, FILTER, &fprog)`
**把它自己的 seccomp 策略装上了**（Android bionic 的 zygote policy，`KILL_PROCESS` 语义）。

内核 seccomp 语义：**多个过滤器叠加，后装的排在前面、判决取最严**。
于是我们这层被彻底盖住 →

* guest 之后每一个 TRAP 都由"它那层"判 → **第一条就 `KILL_PROCESS`**；
* 我们的 handler（`HND#`/`TRAP#`/`[HR]` 全部零输出）、黑匣子（`seq=0`）自然一片空白；
* "死前最后 syscall `nr=0`"其实是**退出码 0 被示踪器当成了 syscall 号**。

**这正是 v0.7.55 ~ v0.7.83 反复"看不见现场"的总根源。**

## 3. v0.7.84 修复：**先装过滤器，再装载**

```c
int sr = vm_sigsys_install(console_fd);      // ① 先把我们的过滤器装上
if (sr != 0) { … _exit(97); }

VmLaunch launch;
int r = vm_loader_prepare(g->map, g->size, &launch);   // ② 再装载（此刻已在保护下）
```

这样装载期 guest 的每一个 syscall（**包括那两个 prctl**）都会先经过我们的 handler；
配合 v0.7.83 已就位的 `prctl` 拦截（`PR_SET_SECCOMP`/`PR_SET_NO_NEW_PRIVS` → 返回 0），
guest 再也装不上它自己的策略。

## 5. 下一轮预期（关键一步）

装 v0.7.84 → 点「运行」。这次应在**装载阶段开头**就看到我们自己的流水：

```
[TwinVM] [4.2dbg] HND#1 nr=… pc=…
[TwinVM] [4.2dbg] HND#2 nr=167 …            ← prctl 被我们拦下（假装成功）
[TwinVM] [HR] nr=…                          ← 裸探针留痕
[TwinVM] 拦截就绪，装载 guest entry=…
… TRAP 编号继续增长 …
```

**只要 TRAP 编号能持续增长**，就说明过滤器由我们独占、ART 启动重新可控 ——
这是自 v0.7.55 以来第一次真正打通这一环。
