## 2. 新问题：`execve` 在 USER_NOTIF 下无法接管

流水走到 `#196 nr=221 execve`（guest 的 `/bin/guest` 要 exec 到 dalvikvm）后就停在
`exit_group(98)`（即 `_exit(98)`）。原因很直接：

* 旧 SIGSYS 后端的 execve 接管是**改 `ucontext` 的 pc/sp 直接跳转**（信号机制特有）；
* USER_NOTIF 只提供"内核在等我们答复"的通道，**没有 ucontext 可改**；
* 而 guest 的 `/bin/probe` / `dalvikvm` 都在 ROM 里，内核无法真的 exec 它们。

## 3. v0.8.1 修法：**不产生这次 execve**

既然 guest 的唯一目的就是"跳进 dalvikvm"，那就**由引擎在装载阶段直接完成**：

```c
if (dv = ROM[/system/bin/dalvikvm]) && (ld = ROM[/system/bin/linker64]) && !LEGACY:
    vm_loader_exec_dyn(dv->map, dv->size, ld->map, ld->size,
                       "/system/bin/dalvikvm", gargv, genvp, &launch);
else:
    vm_loader_prepare(guest->map, guest->size, &launch);   /* 旧路径保留 */
```

`gargv`/`genvp` 与 `guest_stage42.c` **逐字一致**（`dalvikvm -cp /rom/hello.dex Hello` +
`BOOTCLASSPATH` / `DEX2OATBOOTCLASSPATH`（真前缀）/ `ANDROID_*` / `LD_LIBRARY_PATH` / `TMPDIR`）。

于是开局就是 dalvikvm + 真 linker64，**没有任何 execve 系统调用**，
彻底避开 USER_NOTIF 的接管难题。
