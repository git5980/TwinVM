## 2. 卡点：`socket(AF_UNIX, SOCK_RAW|CLOEXEC|NONBLOCK)` 自锁

```
#1402  t7946  nr=198  a0=0x1 a1=0x80802      ← socket(AF_UNIX, SOCK_RAW|...)
#1403  t7947  nr=64   a0=0x5                  ← 另一线程写日志
#1404  t7947  nr=198  a0=0x1 a1=0x0           ← 新线程也 socket()
★ 死前最后 syscall: nr=198
[TwinVM] !! 看门狗：90 秒无任何控制台输出 —— 判定卡死，已强杀槽位
```

**自锁机理**：

1. `socket` 在 NOTIF 集合里 → 被挂起，等监听线程答复；
2. 监听线程把它转给引擎 → 引擎判定 `AF_UNIX` → **"原生放行"** → 引擎**又调一次 `socket()`**；
3. 而这一步发生在**监听线程**里，多线程 + 监听串行 + 内核挂起 → **死锁**。

（另外 `SOCK_RAW` 本身需要 `CAP_NET_RAW`，App 没有 —— 内核会回 `EPERM`，但前提是能走到内核。）

## 3. v0.8.2：socket 由监听线程**直接答复**，不再转交引擎

```c
if (req.data.nr == 198) {
    if (AF_UNIX && (SOCK_STREAM|SOCK_DGRAM))  → 交给引擎（它已有 AF_UNIX 放行语义）
    else                                      → 直接回 -EPERM，**绝不挂起**
    ioctl(NOTIF_SEND); continue;
}
```

要点：**`SOCK_RAW` 等无权限类型直接拒绝**（ART 收到 `EPERM` 会走它的退化路径），
而正常的 `AF_UNIX` 才交给引擎；两种情况都**立即答复**，消除自锁。
