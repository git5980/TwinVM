# TwinVM v0.8.5 —— 隔离守卫：guest 不该看到宿主 fd

> 现场：`twinvm-live.log`（**23 MB**，v0.8.4）—— 仍在 `futex` 停住

## 1. v0.8.4 的成果与残留

* `socket(AF_UNIX) -> 虚拟 fd 20000/20001（假装成功）` ✅ 生效；
* `connect(0x4e21=20001)` 也走"假装成功"✅；
* **但仍在 `futex` 停住**，且卡死前有一段可疑循环：

```
#718   nr=80  fstat(fd=0x64=100, …)          ← ★ fd 100
#721   nr=63  read(fd=100, buf, 0x1000)      ← 反复读
#722   nr=63  read(fd=100, buf, 0x1000)
… （共 418 次涉及 fd=0x64）
```

**`fd=100` 从未被 `openat` 返回过**（全文搜索为 0）—— 它是 **ART 从宿主（App）
继承来的 fd**。也就是说：**guest 正在读写宿主进程的真实 fd**（隔离泄漏），
而且拿到的是"不属于它的内容"，于是进入异常路径、最后停在 futex。

## 2. v0.8.5：真 fd 守卫（read / fstat）

| syscall | 处理 |
|---|---|
| `read(fd)` | 真 fd（3..9999）→ **返回 0（EOF）** 并打一次告警。选 0 而非 `-EBADF`：调用方通常按"读完了"处理，不会重试/断言 |
| `fstat(fd)` | 真 fd → **短路返回 0（空 stat：size/mode/blksize 全 0）**，不写回 guest 缓冲、不给 `EBADF` |

设计原则（与 v0.8.4 一脉相承）：
> **凡是 guest 对"宿主资源"的操作，一律给"友好且无害"的答复** ——
> 既不泄漏宿主，也不让 guest 走进断言/重试/死等。
