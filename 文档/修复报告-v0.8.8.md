# TwinVM v0.8.8 —— 卡点收窄到 `vm_notif_install()` 内部；加逐步打点

> 现场：`twinvm-live.log`（**5.7 KB**，v0.8.7）—— 与 v0.8.6 完全相同

## 1. v0.8.7 的结果：`ioctl` 移出后**卡点未变**

```
[TwinVM] guest 槽位启动 pid=32671：ROM 67 inodes 就绪
[TwinVM] !! 看门狗：90 秒无任何控制台输出 —— 判定卡死
[TwinVM] [bb] 子进程最后的 syscall（seq=0）
```

**"拦截就绪（USER_NOTIF 后端）"这行仍未出现** —— 而它紧跟在 `vm_notif_install()` 成功之后。
对照代码顺序：

```c
vm_log("guest 槽位启动 pid=%d…");        ← 打印了
const VmRomInode* g = vm_rom_find(...);
int sr = vm_notif_install(console_fd);   ← ★ 卡在这里（其后才是"拦截就绪"）
```

**结论：卡点就在 `vm_notif_install()` 内部**（不是监听线程、不是 ioctl）。

## 2. 目前最可疑的一步：`prctl(PR_SET_NO_NEW_PRIVS)`

`vm_notif_install()` 只做三件事：

```c
prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)                       // ①
syscall(__NR_seccomp, SET_MODE_FILTER, NEW_LISTENER, &fprog) // ②
g_listener = fd;                                             // ③
```

而 v0.7.92/93 已经证明：**这个进程天生带着 App（zygote）的 seccomp 过滤器**。
在已有过滤器的情况下，`prctl(PR_SET_NO_NEW_PRIVS)` 或 `seccomp(2)`
**若被那层策略判 KILL，进程会被内核直接杀掉**（连日志都来不及 flush），
症状正是"打完上一行就没了"。

（另一个可能是 ② `seccomp(2)` 被策略拦；两者都能靠打点区分。）

## 3. v0.8.8：三步全部打点 + `PR_SET_NO_NEW_PRIVS` 改为非致命

```c
vm_log("[notif] 步骤0：进入安装（下一步 prctl）…");
int pr = prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
vm_log("[notif] 步骤1：prctl(...) 返回 %d（errno=%d）", pr, pr ? errno : 0);
if (pr != 0) vm_log("[notif] 警告：失败，继续尝试装过滤器");
vm_log("[notif] 步骤2：syscall(seccomp, SET_MODE_FILTER, NEW_LISTENER)…");
   … syscall …
if (fd < 0) { vm_log("[notif] seccomp 失败 errno=%d", errno); return -errno; }
vm_log("[notif] 步骤3：listener fd=%d（安装成功）", g_listener);
```

**设计考虑**：`PR_SET_NO_NEW_PRIVS` 失败**不再直接 return** ——
若进程本来就有 zygote 过滤器，该标志通常已被设置过，无需重复；
继续尝试装我们自己的过滤器往往才是正确的路。

## 4. 下一轮判定表（拿到打点后一步定位）

| 观察 | 结论 | 对策 |
|---|---|---|
| 只有 `步骤0`，没有 `步骤1` | `prctl` 被外层 **KILL** | 完全跳过 `PR_SET_NO_NEW_PRIVS`（直接 `seccomp(2)`） |
| `步骤1` 有，`步骤2` 后无 `步骤3`，`seccomp 失败 errno=…` | `seccomp(2)` 被拒 | 换"**父进程先装再 fork**"：父进程装 listener，子进程继承 |
| `步骤3` 出现 | 安装成功 | 卡点在后（监听线程/装载），继续按流水排查 |
| 连 `步骤0` 都没有 | 卡在 `vm_log` 之前 | 查 console fd 与日志通道 |

## 5. 验证

* `make -C core test` 5/5 PASS；`checkrom --strict` PASS；ROM md5 未变；
* APK `versionCode=125 / versionName=0.8.8`，同源签名。

## 6. 备用方案（若确认是策略问题）

**父进程先装、子进程继承**：
在 `fork()` **之前**用 `SECCOMP_FILTER_FLAG_NEW_LISTENER` 装好过滤器并拿到 listener fd，
子进程 fork 后**继承该 fd 与过滤器**（`seccomp` 过滤器跨 fork 继承，listener fd 亦然）。
这样"安装"发生在**还未受 guest 影响**的父进程里，规避一切时序问题。
