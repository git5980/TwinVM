# TwinVM v0.8.9 —— 界面实时显示运行进度（不再干等 90 秒黑屏）

> 需求（用户）："不要就显示一个运行中，干等着难受，把运行到哪一步、运行结果显示出来"

## 1. 界面侧：实时刷新（每 400ms）

`MainActivity` 新增 ticker 线程：运行期间每 **400ms** 读一次 `twinvm-live.log` 尾部，
把界面刷新成：

```
⏱ 已运行 12 秒 ｜ 日志 47 KB
───────────────────────
[TwinVM] ▶ [4/6] 装载 dalvikvm + linker64…
[TwinVM] exec_dyn: exe bias=0x73089c0000 linker bias=0x723c158000 …
[TwinVM] ▶ [5/6] ✓ 装载完成 entry=0x723c1a9000，跳转入 guest（ART 启动）
```

* **随时知道"跑到哪一步 / 已经多久 / 日志多大"**，不再是"…运行中"；
* 运行结束自动停止刷新并显示完整结果（原有逻辑不变）；
* 新增 `readTail()` 工具（`RandomAccessFile` 读尾部，按行对齐，避免半行乱码）。

## 2. 通知栏进度（切后台也能看）

每 400ms 同步一条**常驻通知**（id 1001，`IMPORTANCE_LOW`，不响铃）：

```
TwinVM 运行中 · 12 秒
▶ [4/6] 装载 dalvikvm + linker64…
```

* 取 tail 里**最后一条非 `[trace]` 行**（避免显示刷屏的 syscall 流水）；
* 用 `BigTextStyle` 展开可看更完整上下文；
* 运行结束 `nm.cancel(1001)` 清理；
* 已加 `POST_NOTIFICATIONS` 权限（Android 13+；即便用户拒绝，也只是不显示通知，功能不受影响）。

## 3. 引擎侧：六阶段打点（带 ▶ 前缀，界面/日志双通道可见）

```
▶ [1/6] 槽位启动 pid=…，ROM 67 个文件就绪
▶ [2/6] 安装拦截器（USER_NOTIF）…        ← 卡住时这里就是最后一行
▶ [2/6] ✓ 拦截器就绪（USER_NOTIF, listener fd=3）
▶ [3/6] ✓ 监听线程已启动
▶ [4/6] 装载 dalvikvm + linker64…
▶ [5/6] ✓ 装载完成 entry=0x…，跳转入 guest（ART 启动）
▶ [6/6] 已进入 ART，后续输出见下方实时日志
```

**意义**：真机卡死时，**界面最后一行就是卡在哪一步**，不用等日志导出即可判断；
针对当前"卡在 [2/6] 之前"的问题，用户下次运行会**直接在屏幕上看到**
是走到了 `[1/6]` 还是 `[2/6]`，一步定位。

（旧 SIGSYS 分支同样加了 `▶ [2/6]` 打点，回退模式也可用。）

## 4. 验证

* Java 编译通过（无 lambda，沿用匿名内部类纪律）；引擎编译通过；`make -C core test` 5/5；
* `checkrom --strict` PASS；ROM md5 未变；
* APK `versionCode=126 / versionName=0.8.9`，同源签名。

## 5. 下一轮用法

1. 装 v0.8.9 → 点「运行」；
2. **眼睛盯着界面**：最后一行 `▶ [N/6]` 就是当前进度；
3. 若停在 `[1/6]` 或 `[2/6]`（就是当前这个 bug），界面会立刻告诉你，
   同时通知栏也同步 —— 不再有"90 秒黑屏"的体验。
