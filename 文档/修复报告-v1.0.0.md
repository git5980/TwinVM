# TwinVM v1.0.0 —— 换后端：**ptrace 拦截**（seccomp 已被系统彻底封死）

> 现场：`twinvm-20261014-214851.log`（v0.9.1）—— 三轮实验的最终结论

## 1. v0.9.1 的决定性读数：三条 seccomp 路线全部被封

```
▶ [2/6] 安装拦截器（USER_NOTIF）…
▶ [2/6] seccomp(2) 被挂起 → 强制使用 SIGSYS/TRAP 后端       ← 3 秒超时判定生效 ✅
[notif] 安装前 prctl(PR_GET_SECCOMP)=2（App 天生带过滤器）
自检：马上触发一次 TRAP（faccessat）…  → code=-31 SIGSYS      ← 信号永不投递
```

| 路线 | 尝试 | 结果 |
|---|---|---|
| A. `SECCOMP_RET_USER_NOTIF` | `seccomp(SET_MODE_FILTER, NEW_LISTENER)` | **调用被永久挂起**（外层策略把它当需外部应答的操作） |
| B. `SECCOMP_RET_TRAP` + SIGSYS | 自检 TRAP | **SIGSYS 永不投递**（外层判 KILL 压过 TRAP） |
| C. 放行清单对齐 | 全量审计 | 已做到零交集，但仍无解（问题在机制，不在配置） |

**结论：这台设备上，"应用自己安装 seccomp 过滤器"这条路被系统策略彻底封死。**

## 2. v1.0.0：改用 **ptrace 后端**（项目里唯一已验证可用的拦截通道）

**为什么可行**：Android 上对自己 `fork` 的子进程用 `ptrace` 是允许的 ——
而且本项目的**示踪器线程早已稳定工作**（v0.7.65 起，累计 336K 事件全量记录）。
把它从"只观察"升级为"**拦截 + 改写返回值**"即可，**完全不碰 seccomp**。

### 实现（`tvm_tracer_main` 内）

```c
// ① entry 停点：需要虚拟化的号 → 把 x8 设为 -1（内核直接返回 ENOSYS = "跳过"），记待办
if (tvm_virt_nr(nr)) {
    tvm_getregs(t, &rr);
    tvm_virt_set(t, nr);
    rr.regs[8] = -1;             // x8 = syscall 号 → -1 使内核不执行
    tvm_setregs(t, &rr);
}
// ② exit 停点：有待办 → 用引擎算出结果，写回 x0（返回值寄存器）
if (op == PSI_EXIT) {
    long pending = tvm_virt_take(t);
    if (pending >= 0) {
        tvm_getregs(t, &rr);
        long res = vm_handle_syscall(cpu, pending, x0..x5);   // 复用引擎全部语义
        rr.regs[0] = res;
        tvm_setregs(t, &rr);
    }
}
```

**关键优势（对比 seccomp 方案）**：
* **无自递归问题** —— ptrace 是"父进程管子进程"，拦截者不在被拦截的进程里；
* **无信号依赖** —— 不担心 SIGSYS 被屏蔽/被外层 KILL 压过；
* **无监听线程** —— 不需要 `ioctl(RECV/SEND)`，也就没有 v0.8.3~v0.8.7 那一串自锁；
* **引擎零改动** —— `vm_handle_syscall()` 原样复用（虚拟 fd、ROM 读、/proc 合成、tee 全在）。

### 启用逻辑

```
seccomp(2) 3 秒内未返回 → g_notif_suspended = 1
   → 子进程不装任何 seccomp，标记 g_ptrace_backend = 1
   → 输出：▶ [2/6] ✓ 拦截器就绪（**ptrace 后端**：seccomp 已被系统封死）
```

然后 **ART 的 syscall 将被 ptrace 逐个拦截/改写**（不再有任何 seccomp 限制），
流水应当继续增长；即便某个号处理不当，也只会表现为"该 syscall 返回 ENOSYS"，
而**不会**像 seccomp 那样直接把进程 KILL 掉 —— **可控性大幅提升**。
