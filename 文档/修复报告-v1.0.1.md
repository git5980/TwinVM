# TwinVM v1.0.1 —— **ptrace 后端成功**！修"拦了不该拦的号"（270 导致 SIGSEGV）

> 现场：v1.0.0 运行 **400+ 秒**（用户实测）—— 说明**它真的跑起来了**，而不是黑屏干等

## 1. 里程碑：ptrace 后端通过了全部 6 个阶段

```
▶ [1/6] 槽位启动 pid=…，ROM 67 个文件就绪
▶ [2/6] seccomp(2) 被挂起 → ✓ 拦截器就绪（ptrace 后端）
▶ [3/6] ✓ 监听线程已启动
▶ [4/6] 装载 dalvikvm + linker64…
▶ [5/6] ✓ 装载完成 entry=0x723bbbb000，跳转入 guest（ART 启动）
▶ [6/6] 已进入 ART，后续输出见下方实时日志        ← ★★ 自 v0.7.55 以来第一次走到这里
```

**这是整个项目第一次在没有 seccomp 的情况下，把 ART 的入口跑起来。**
（原因：这台设备上 seccomp 被系统彻底封死 —— A/B/C 三条路线全灭；ptrace 是唯一出路。）

## 2. 新问题：ptrace 拦了 `process_vm_readv`，把 guest 搞崩了

```
GUEST FAULT: sig=11 addr=0xf3 pc=0x723bc0df3c
  x0=0xf3   ← 访问 0xf3（非法指针）
[trace] #132..#139  nr=270  process_vm_readv(0x30b6, …)   ← ★ 连续 8 次重试
[trace] #140  nr=64  write(0x88, …)
[trace] #142  nr=94  exit_group(0x59=89)
```

**因果链**：`v1.0.0` 的 `tvm_virt_nr()` 把 `270/271` 也列进了"要虚拟化" →
被 ptrace **跳过**（x8=-1）→ 引擎的 `process_vm_readv` 实现在这个上下文里
给出的返回值不符合调用方预期 → 调用方拿到垃圾指针 `0xf3` → **SIGSEGV**。

**教训**：`process_vm_readv/writev` 是**引擎自己的安全访存原语**，
**绝不能被我们自己的拦截层改写** —— 这和 v0.7.76（seccomp 放行清单里留着它们）
是同一个错误的两个变体：
* seccomp 版：放行了它 → 绕过 handler；
* ptrace 版：拦下了它 → 返回值被破坏。

**两种情况下答案一致：把它们从"虚拟化集合"里拿掉，让它走真实内核。**

## 3. v1.0.1 修法：显式"不拦截"清单

```c
/* 明确不拦截：让它们走真实内核 */
case 270: case 271:   /* process_vm_readv/writev —— 引擎自己的原语，改写会崩 */
case 222: case 226: case 215: case 214:   /* mmap/mprotect/munmap/brk —— 内存原语 */
case 98:  case 220:   /* futex / clone —— 线程基础设施 */
case 135: case 132:   /* rt_sigprocmask / sigaltstack */
case 94:  case 93:    /* exit_group / exit */
case 172..178:        /* getpid/gettid/uid/gid —— 同进程，真实值本就正确 */
    return 0;
```

同时**加了后端心跳**（每 2000 个 syscall 写一条）：

```
[TwinVM] ▶ 已虚拟化 2000 个 syscall（最近 nr=63 tid=12470）
```

**解决"400 秒无输出、不知道在干嘛"的问题** —— 界面/通知栏会持续显示进度。

## 4. 验证

* `make -C core test` 5/5 PASS；`checkrom --strict` PASS；ROM md5 未变；
* APK `versionCode=131 / versionName=1.0.1`，同源签名。

## 5. 下一轮预期

装 `TwinVM-Stage4-v1.0.1-ptrace.apk` → 点「运行」：

* 界面/通知栏会**持续刷新**：`已虚拟化 N 个 syscall` + 最近 syscall + 已运行秒数；
* 若 `process_vm_readv` 不再被破坏 → 不再有 `x0=0xf3` 那类野指针 → ART 能继续往下走；
* 若再崩，崩溃现场（`GUEST FAULT` + backtrace + recent syscalls）会立刻出现在界面，
  我们可以按同样的方式精确定位 —— **而且不会再有"不知道跑到哪"的情况**。
