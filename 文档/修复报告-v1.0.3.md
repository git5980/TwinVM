# TwinVM v1.0.3 —— ★ ptrace exit 停点用错了寄存器：把"返回值"当"参数"

> 现场：`twinvm-live.log`（13 KB，v1.0.2）

## 1. v1.0.2 的互斥生效了（只剩一个后端）

```
▶ [2/6] ✓ 拦截器就绪（**ptrace 后端**：seccomp 已被系统封死）
▶ [3/6] ptrace 模式：跳过监听线程（拦截在示踪器里完成）
▶ [4/6] 装载 dalvikvm + linker64…
▶ [5/6] ✓ 装载完成 entry=0x71effe8000，跳转入 guest（ART 启动）
▶ [6/6] 已进入 ART
GUEST FAULT: sig=11 addr=0xf3 pc=0x71f003af3c
```

**双后端问题已解决**（日志里只有一条后端声明）。但崩溃点与前两次**完全一致**：
`x0=0xf3`、同一 `pc`、同样 backtrace —— 说明这是**确定性 bug，不是竞态**。

## 2. 定位：崩溃在 linker64 的 `itanium_demangle`（C++ 名字反解）里

```
pc - linker_bias = 0xa3f3c
0xa3f3c 落在 __dl__ZN12_GLOBAL__N_116itanium_demangle…parseEncoding/parseType 之间
```

即 **linker 在反解 C++ 符号名时读了一个坏指针**（`addr=0xf3`）。
而 `x0=0xf3`(=243) 这个数值非常可疑 —— **243 正是前一条 `process_vm_readv` 返回的字节数**：

```
#105..#112  nr=270 process_vm_readv(0x553d, …) ×8     ← 返回 243 字节
#113        nr=64  write(0x75, …)
GUEST FAULT addr=0xf3  x0=0xf3                          ← 243 被当成指针
```

**结论**：guest 拿到了**本不该属于它的返回值** —— 是**我们的 ptrace 层写错了某个 syscall 的返回值**。

## 3. 真凶：`PSI_EXIT` 停点用寄存器当参数

v1.0.0 的实现：

```c
if (op == PSI_EXIT) {
    long pending = tvm_virt_take(t);          // ① 只按 tid 匹配（会张冠李戴）
    tvm_getregs(t, &rr);
    long res = vm_handle_syscall(cpu, pending,
                (long)rr.regs[0], (long)rr.regs[1], ...);  // ② ★ 用 exit 停点的寄存器当参数！
    rr.regs[0] = res;                          // ③ 再写回 x0
}
```

**两处致命错误**：

| # | 错误 | 后果 |
|---|---|---|
| ① | 待办只按 **tid** 匹配 | 若该 tid 上有多个待办交错，就会取错 syscall 号 |
| ② | 用 **exit 停点的 `x0..x5`** 当参数传给引擎 | exit 停点时寄存器里**已是返回值**（x0）或**已被内核清空** —— 引擎等于拿垃圾参数执行，然后我们把垃圾结果**写回 x0** → guest 拿到 `0xf3` 这种值当指针用 → SIGSEGV |

## 4. v1.0.3 修法

1. **entry 停点就把参数存进待办表**：
   ```c
   struct tvm_virt_slot { pid_t tid; long nr; int active; unsigned long long args[6]; };
   tvm_virt_set(t, nr, info.u.entry.args);      // ← 参数来源改为 entry 现场
   ```
2. **exit 停点取待办时校验 syscall 号**：
   ```c
   int pending = tvm_virt_take(t, (long)info.u.exit_stop.nr, sv);   // 号不一致 → 不处理
   long res = vm_handle_syscall(cpu, pending, sv[0]..sv[5]);        // 用 entry 保存的参数
   rr.regs[0] = res;                                               // 只改返回值
   ```
3. 补上 `tvm_psi` 结构里缺失的 **exit 停点成员**（内核 `ptrace_syscall_info` 的 `op=2` 分支）。

**一句话**：`entry` 拿参数、`exit` 写返回值 —— **两者绝不能混用寄存器快照**。
