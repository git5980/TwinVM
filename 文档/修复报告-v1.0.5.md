# TwinVM v1.0.5 —— ★ 显式处理 `PTRACE_EVENT_CLONE`（线程创建的最后一道门）

> 现场：`twinvm-live.log`（**26.6 MB**，v1.0.4）—— 又是数量级增长

## 1. v1.0.4 的读数：刷屏但不是多线程

```
线程列表: 只有 t11784                      ← 仍然单线程
clone 日志: 无                             ← 根本没走到 clone
刷屏统计: nr=227(msync) 8.8万 / nr=222(mmap) 5.6万 / nr=215(munmap) 5.6万
卡死前: #357319 nr=98 futex(0xb400007237866984, 0x80, 0x3)
```

**两个观察**：
1. **刷屏**（26.6 MB）全是 **ART 的 GC 循环**（`mmap/munmap/msync`），把真正的现场淹没了；
2. **仍单线程**、`futex` 依然死等 —— 而我 v1.0.4 加的 `sig == SIGSTOP` 分支**从未被触发**
   （日志里没有"初始停点"行）。

## 2. 为什么 v1.0.4 没接住新线程停点

开了 `PTRACE_O_TRACECLONE | PTRACE_O_TRACESYSGOOD` 之后，**`clone` 事件**的表现是：

```
waitpid 状态 => (SIGTRAP | (PTRACE_EVENT_CLONE << 8)) << 8
                即 WSTOPSIG(st) != SIGTRAP|0x80，也不是 SIGSTOP
```

而我的分支顺序是：

```c
if (sig == (SIGTRAP | 0x80)) { … syscall 停点 … }
else if (sig == SIGTRAP)     { … PTRACE_EVENT 或真 SIGTRAP，不注入 … }
else if (sig == SIGSTOP && t != g_t_pid) { … 吞掉 … }      ← v1.0.4 加在这里
else { … 转发真信号 … }
```

`PTRACE_EVENT_CLONE` **落进了 `sig == SIGTRAP` 那一支**（因为 `WSTOPSIG` 就是 `SIGTRAP(5)`），
于是：**新线程被创建出来、在初始停点等我们，而我们既没有取 `PTRACE_GETEVENTMSG`
拿新 tid，也没有显式 `PTRACE_SYSCALL` 续跑它** —— 只是把父线程继续了。
**新线程永远停在初始停点** → ART 主线程 `futex` 死等。

（v1.0.4 的 `SIGSTOP` 分支写得没错，只是**根本轮不到它**。）

## 3. v1.0.5 修法（两处）

### (a) 显式处理 `PTRACE_EVENT_CLONE`

```c
} else if ((st >> 8) == (SIGTRAP | (PTRACE_EVENT_CLONE << 8))) {
    unsigned long newtid = 0;
    ptrace(PTRACE_GETEVENTMSG, t, 0, &newtid);          // 取新线程 tid
    vm_log("[trace] ★ PTRACE_EVENT_CLONE：父 t=%d → 新线程 tid=%lu（显式续跑）", t, newtid);
    if (newtid > 0) ptrace(PTRACE_SYSCALL, (pid_t)newtid, 0, 0);   // ★ 让新线程跑起来
    ptrace(PTRACE_SYSCALL, t, 0, 0);                                // 父线程继续
}
```

### (b) trace 只记录"被拦截的" syscall

```c
int tvm_intercepted = tvm_virt_nr((long)info.u.entry.nr);
int k = tvm_intercepted ? snprintf(...) : 0;    // 未拦截的（GC 循环）不再写日志
```

**效果**：日志从 26 MB 降到**几 KB 级**，真正有用的现场（被虚拟化的 syscall +
线程事件）一眼可见；同时保留"每 2000 次"的心跳。

## 5. 下一轮预期

装 `TwinVM-Stage4-v1.0.5-ptrace.apk` → 点「运行」，日志里应出现：

```
[trace] ★ PTRACE_EVENT_CLONE：父 t=11784 → 新线程 tid=11902（显式续跑）
[trace] #…  t11902  nr=178 …            ← 新线程开始产生自己的 syscall
```

**只要出现第二条线程的流水**，就说明 ART 的多线程环境终于建立 ——
主线程的 `futex` 会被唤醒，Runtime 初始化可以继续（这是 v0.7.55 以来从未到过的地方）。
