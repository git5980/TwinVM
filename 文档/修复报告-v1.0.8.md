# TwinVM v1.0.8 —— ★★ 关键发现：ptrace "跳过"了 syscall，但**结果没有回填**（guest 拿到 ENOSYS）

> 现场：`twinvm-live.log`（120 KB，v1.0.7）

## 1. v1.0.7 的读数：清理**确实执行了**（只是日志丢了）

```
#248  nr=57  close(0xfc=252)      ← ★ 我的清理循环！
#249  nr=57  close(0xfd=253)
#250  nr=57  close(0xfe=254)
#251  nr=57  close(0xff=255)
#252  nr=64  write(fd=2, …)
#253  nr=64  write(fd=0x91=145, …)  ← console
▶ [1/6] 槽位启动 pid=21860 …
```

**清理循环在跑**（fd 252~255 被关），但**"槽位已清理"那行没出现** ——
原因是 `vm_log` 的写与 `close` 在同一时间窗，日志 fd 被波及。→ **v1.0.8 把顺序改成
"先设 console + 先打日志，再清理"**（并在清理后再打一条确认）。

## 2. ★ 真正的大发现：`openat` 被拦了 126 次，**引擎一次都没被调用**

```
nr=56 (openat) 出现 126 次        ← ptrace 确实拦下了
但如果搜引擎自己的日志：
  openat("/…") -> fd=…            ← 0 条！
```

**这说明**：ptrace 在 entry 停点把 `x8` 改成 `-1`（让内核跳过），
但**在 exit 停点没有把引擎算出的结果写回** → **guest 拿到的是 `ENOSYS`**。

**为什么没回填？** v1.0.3 加的号校验太严：

```c
int pending = tvm_virt_take(t, (long)info.u.exit_stop.nr, sv);
…
if (nr >= 0 && got != nr) return -1;      // ← 号不一致 → 放弃回填
```

而**我们已经把 x8 改成了 -1**，内核在 exit 停点报的 `nr` 就是 **`-1`**（或 0）——
于是在"放宽条件"下（`nr >= 0` 且 `-1 != 原号`）……实际上 `-1 >= 0` 为假本不该拦，
但**只要内核报的是 0 或其它值，就会误判为"不是这次"** → **放弃回填**。

而 `read(fd=5)` 的 `fd=5` 正是**这种"拿到 ENOSYS 之后 ART 自己的退化路径"**产生的连锁反应：
ART 把一个失败/异常的值当 fd 继续用 → 反复 read → 重试 → futex 死等。

## 3. v1.0.8 修法（两处）

### (a) 号校验放宽：只在"报了**不同且为正**的号"时才判不匹配

```c
/* 内核在 exit 停点报的 nr 可能是：原号 / -1（我们改过 x8）/ 0。 */
if (nr > 0 && got != nr) return -1;
```

### (b) 回填留痕（每 200 次记一条）

```c
vm_log("[ptrace] 回填 #%d：nr=%d → x0=%ld（tid=%d）", s_fill, pending, res, (int)t);
```

**这条日志是"跳过 + 回填"链路是否真的在跑的判据** —— 之前只看到"拦下"，
从没验证过"填回"，这正是漏掉的一环。

## 4. 验证

* `make -C core test` 5/5 PASS；`checkrom --strict` PASS；ROM md5 未变；
* APK `versionCode=138 / versionName=1.0.8`，同源签名。

## 5. 下一轮判定（两条日志定生死）

装 `TwinVM-Stage4-v1.0.8-ptrace.apk` → 点「运行」，看：

| 日志 | 含义 |
|---|---|
| `▶ 槽位启动：清理继承的宿主 fd …` + `▶ 槽位 fd 清理完成` | 顺序修复生效 |
| `[ptrace] 回填 #1：nr=56 → x0=10000`（等） | **回填链路真的在跑** ← 本轮核心 |
| 引擎日志里出现 `openat("/system/…") -> fd=…` | 说明虚拟化真正生效 |

**若"回填"日志出现、且引擎 `openat` 日志开始刷出** → ptrace 后端的
"拦截 → 交引擎 → 回填"闭环**第一次真正打通**，ART 的 syscall 语义才算完整。
