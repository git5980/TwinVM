# TwinVM v1.0.9 —— 回填仍为零：把"寄存器访问失败"变成可见错误 + 修正 fd 清理过度

> 现场：`twinvm-live.log`（30 KB，v1.0.8）

## 1. v1.0.8 的部分成功与残留

**成功**（fd 清理顺序修复生效，两条日志都出现了）：

```
▶ 槽位启动：清理继承的宿主 fd（保留 console=137）…
▶ 槽位 fd 清理完成（保留 console=137）
```

**残留（两个问题）**：

| 观察 | 含义 |
|---|---|
| `[ptrace] 回填 #…` **0 条** | 回填链路**依然没跑** |
| 引擎 `openat("…") -> fd=…` **0 条** | 引擎**从未被调用** |
| 卡死点从 1444 **提前到 348** | **fd 清理治过头了** |

## 2. 问题一：fd 清理"治过头"

v1.0.7/1.0.8 的清理是 `for (fd = 3; fd < 256; fd++) close(fd)` ——
把 **ART/loader 依赖的 fd**（除了 console）也一并关掉了，
于是 loader 早早失败，卡死点**从 1444 提前到 348**。

**而真正要治理的是"高位宿主 fd"**（之前看到的 `fd=99` 就属于这类），
`3..63` 是 loader 的常用区间，应当保住。

→ **v1.0.9：只关 `fd >= 64`**，并统计关掉的数量：

```c
int closed = 0;
for (int fd = 64; fd < 512; fd++)
    if (not in keep) { if (close(fd) == 0) closed++; }
vm_log("▶ 槽位 fd 清理完成（关掉 %d 个高位 fd，保留 console=%d）", closed, console_fd);
```

## 3. 问题二（核心）：回填为零 —— 但原因**还没被看见**

`回填` 日志没出现，只有两种可能：
* ① **entry 停点的 `PTRACE_GETREGSET`/`SETREGSET` 失败** → 根本没记待办、也没改 x8；
* ② **exit 停点没被识别**（`info.op != 2`）或 `GETREGSET` 失败 → 无法回填。

但**这两种失败之前都是静默的**（`if (tvm_getregs(...) == 0)` 不成立就直接跳过），
所以日志里什么都看不到 —— **这正是"排查卡住"的原因**。

→ **v1.0.9：把所有寄存器访问失败显式打出来**（限流各 5 条）：

```c
long gr = tvm_getregs(t, &rr);
if (gr != 0 && s_gr++ < 5)
    vm_log("[ptrace] !! GETREGSET 失败 errno=%d（tid=%d）—— 无法改 x8", errno, t);

if (tvm_setregs(t, &rr) != 0 && s_sr++ < 5)
    vm_log("[ptrace] !! SETREGSET 失败 errno=%d（tid=%d）", errno, t);

/* exit 侧同理 */
vm_log("[ptrace] !! exit GETREGSET 失败 errno=%d —— 无法回填", errno);
```

**这是本轮真正的价值**：把"静默失败"变成"可诊断错误"。

## 5. 下一轮判定表（这次一定能定位）

装 `TwinVM-Stage4-v1.0.9-ptrace.apk` → 点「运行」，对照：

| 日志 | 结论 | 下一步 |
|---|---|---|
| `!! GETREGSET 失败 errno=N` | 寄存器读取方式不对（NT_PRSTATUS/iovec） | 改用 `PTRACE_GETREGS`（若内核支持）或修正 iovec |
| `!! SETREGSET 失败 errno=N` | 同上（写侧） | 同上 |
| `!! exit GETREGSET 失败` | exit 侧读不到 | 同上 |
| **`[ptrace] 回填 #1：nr=56 → x0=…`** | **链路跑通** | 继续看 ART 是否推进 |
| 以上都没有、但引擎 `openat` 日志出现 | 说明回填静默成功 | 直接看 ART 表现 |

## 7. 方法论提醒（这条很重要）

> 连续三轮我都在"猜为什么回填不生效"，而真正的障碍是
> **关键失败路径没有日志**。把 `if (ok) { … }` 补上 `else { 打错误 }`，
> 比再读三遍代码有效得多 —— **静默失败是排查最大的敌人**。
