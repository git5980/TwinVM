# TwinVM v1.1.2 —— ★★★ 真凶落网：exit 停点用 `nr=-1` 匹配待办，导致**所有 syscall 都被回填成 close 的结果**

> 现场：`twinvm-live.log`（46 KB，v1.1.1）—— **通道修好后，问题一秒现形**

## 1. GSI 原始值（第一次看清内核到底给了什么）

```
[ptrace] GSI: r=80 op=1 arch=3221225655 nr=64（t=10365）   ← entry
[ptrace] GSI: r=33 op=2 arch=3221225655 nr=-1（t=10365）   ← exit
[ptrace] GSI: r=80 op=1 arch=3221225655 nr=57
[ptrace] GSI: r=33 op=2 arch=3221225655 nr=-1
...
[ptrace] 回填 #1：nr=57 → x0=-9
[ptrace] 回填 #201：nr=57 → x0=-9
[ptrace] 回填 #401：nr=57 → x0=-9
```

**三个结论**：

| 事实 | 说明 |
|---|---|
| `op==1 / op==2` | ✅ **我原来的假设是对的**（entry/exit 都正确识别） |
| `arch=3221225655 = 0xC00000B7` | ✅ aarch64，正确 |
| `r=80 / 33` | ✅ `PTRACE_GET_SYSCALL_INFO` 写入的字节数 |
| **`nr=-1`（exit）** | ⚠️ 因为**我们在 entry 把 x8 改成了 -1**，exit 时自然报 -1 |
| **`回填 nr=57 → x0=-9`** | ★★★ **全部回填的都是同一个 syscall（close）的结果** |

## 2. 真凶：v1.0.8 的"号校验放宽"引入了严重错误

```c
// v1.0.8 写的（我当时以为在"放宽"）：
if (nr > 0 && got != nr) return -1;      // ← nr=-1 时条件为假 → 根本不校验！

// 于是 tvm_virt_take 直接返回该 tid 的**第一条**待办
```

**后果链**：

1. `close(57)` 被反复拦截 → 待办表里堆了很多条（每 tid 一条以上）；
2. **任何** syscall 的 exit 停点，`nr` 都是 `-1` → 校验被跳过 → 取到**第一条待办**（恰好是 `close`）；
3. 于是**所有 syscall 的 `x0` 都被写成 `close` 的返回值 `-EBADF(-9)`**；
4. guest 处处拿到 `-9` → 行为完全错乱（这也解释了此前那些"莫名其妙"的失败）。

## 3. v1.1.2 修法：entry/exit **严格 FIFO 配对**

```c
struct tvm_virt_slot { pid_t tid; long nr; int active;
                       unsigned long long args[6];
                       unsigned long long seq; };   /* v1.1.2：入队序号 */

static void tvm_virt_set(pid_t tid, long nr, ...) {
    ... g_virt[i].seq = ++g_virt_seq;               /* entry 时打序号 */
}

static int tvm_virt_take(pid_t tid, long nr, ...) {
    (void)nr;   /* ★ exit 停点的 nr 已被我们改成 -1，没有信息量 —— 不再用它匹配 */
    int best = -1; unsigned long long best_seq = ~0ULL;
    for (...) if (active && tid 相同 && seq < best_seq) { best = i; best_seq = seq; }
    ...                                             /* ★ 取**同一 tid 中最小的 seq** = FIFO */
}
```

**要点**：
* **不再依赖 `nr` 匹配**（它已被我们改掉，本来就不可信）；
* 改为 **同一 tid 内按 seq 先进先出** —— 与 ptrace 的 entry/exit 天然配对顺序一致；
* 多线程场景下 tid 隔离，不会串。
