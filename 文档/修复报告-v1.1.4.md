## 2. 判读纠偏（对自家日志对数之后的三个结论）

### 2.1 ".so 是否最新" → **解除**

README 遗留问题"v1.1.3 日志与 v1.1.2 完全一致"。实际两日志唯一的语义差异：

```
v1.1.2: [ptrace] 回填 #201：nr=57 → x0=-9     ← close 回 EBADF
v1.1.3: [ptrace] 回填 #201：nr=57 → x0=0      ← close 回 0（v1.1.3 修复生效）
```

修复已生效，APK 里的就是新构建。（另证：本机重编 .so 与 zip 内 .so 导出符号表
0 差异；`make -C core test` 5/5 PASS。）

### 2.2 "close 风暴 446 次重试" → **证伪**

对 live-v1.1.3.log 全部 close 事件做 fd 直方图：

- 457 次 close 事件中 **449 个不同 fd（0x40→0x1ff 单调递增），零重复**；
- "槽位 fd 清理完成（关掉 446 个高位 fd）"正是这段——**一次性启动清理**，
  每个继承来的宿主 fd 关一次，不是 ART 拿 EBADF 后的重试死循环；
- ART 入口后的 31 个拦截事件里 close 出现 **0 次**。

> close 对真 fd 假装成功（v1.1.3 修复）本身仍是正确的防御性语义，保留；
> 但"风暴→卡 300 秒"的因果链不成立。300 秒的主嫌疑是**启动期扫雷**（50 秒
> 时间预算用尽在 nr=321）+ 446 次 ptrace 拦截的逐 fd 开销，待验。

### 2.3 真实状态：ART 入口后 31 syscall → EXIT=0

```
[6/6] 已进入 ART
#459 set_tid_address → #460 faccessat → #461-468 prctl(PR_SET_VMA)×8
#469-471 fcntl(0/1/2, F_GETFL) → #472 newfstatat → #473 openat
#474-476 … → #477 writev(fd=2) → #478 socket(AF_UNIX)
#479 writev(fd=2) → … → #486 prctl(PR_SET_DUMPABLE)
#487 prctl(PR_SET_PTRACER) → #488 socket → #489 writev(fd=2)
[EXIT=0]
```

三个判断：① 干净退出（exit_group 走审计放行，不经 trace）非崩溃；
② **3×writev(fd=2) 就是 ART 临终写给 stderr 的报错原文**——但 trace 行只记
参数指针，内容没进 live 日志，等于 abort 原因还在黑洞里；
③ 31 个 syscall 太短，不像完整 Runtime init——更像 usage/参数类错误路径。

## 3. 本轮改动

### 3.1 v1.1.4 ★ write/writev(fd≤2) payload 抄送（[tee]）

- 位置：示踪线程 entry 停点（tracee 静止、参数内存完整）；
- 原语：**PTRACE_PEEKDATA**（零新 syscall，不碰外层 seccomp 红线；
  process_vm_readv(270) 虽不在扫雷 KILL 名单，PEEKDATA 仍是风险最低选择）；
- writev 先读 iov 数组（≤8 项）再逐段读 payload，单条截断 200B、ASCII 化、
  限流 64 条防后期刷屏；输出形如
  `[TwinVM] [tee] fd=2 writev（92 B）: E/dalvikvm: ...`。

### 3.2 可移植性修复（x86_64 宿主跑离线回归被编译器拦下）

`vm_backend_sigsys.c` 三处裸 arm64 内联汇编无 `__x86_64__` 守卫（v0.7.85/v0.7.93
引入，TA 侧 aarch64 容器编得过、本机 x86_64 编不过）→ 按同文件既有惯例补齐；
其中 **[HR] 探针（v0.7.81）原有真 bug**：7 个 `"r"` 操作数但指令串不引用 `%N`，
寄存器由编译器随机分配而 `svc` 固定读 x0-x6——arm64 上写的实为随机寄存器。
两侧都改为固定寄存器约束的正确写法。

### 3.3 工程链

- `tools/build_android_here.sh`：clang 资源目录随 NDK 版本自动探测（可覆盖）；
- `android/build.sh`：源列表补 `vm_notif.c`（v1.x 新增文件漏登记）、
  产物改名 `TwinVM-Stage4-v1.1.4.apk`；
- AndroidManifest：versionCode 143→**144** / versionName 1.1.3→**1.1.4**。

## 6. 本轮教训（第三类：**诊断必须和自家日志对数**）

> "446 次 close 占 87%"是**数出来**的，但"风暴/重试"是**脑补**的——
> 一张 fd 直方图就能证伪。写结论前先对数：fd 重复吗？单调吗？发生在哪个阶段？
> 数字对得上≠因果对得上。
