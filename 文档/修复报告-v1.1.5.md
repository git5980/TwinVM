# TwinVM v1.1.5 —— 真凶现形前的最后一层观测（[sig] 全记录 + tee 扩面）

> 输入：v1.1.4 真机日志（twinvm-live.log，601 行）。v1.1.4 的 [tee] 抓到了
> **`libc: failed to set traceable: Operation not permitted`**——但判读之后发现
> 这不是根因，是**临终遗言**。真凶还需要一层观测才能现形。

## 1. v1.1.4 日志判读（结合 linker64 反汇编，证据链完整）

### 1.1 "failed to set traceable" 的真实身份

ROM 里 strings 定位：该串在 `system/bin/linker64` 的
**`debuggerd_signal_handler(int, siginfo_t*, void*)`** 内（0x100f30，失败走
`fatal_errno`）。反汇编判决：

```
0x100b40  prctl(PR_SET_DUMPABLE, 1)          ← 日志 #486 ✓
0x100b9c  prctl(PR_SET_PTRACER, ANY)         ← 日志 #487 ✓（EPERM）
0x100bbc  if (si 不是 SIGSEGV) → fatal_errno("failed to set traceable")
```

**结论：这两条 prctl 只有在致命信号（SIGSEGV/SIGBUS/…）触发
debuggerd 信号处理器时才会执行。guest 在 #485~#486 之间已经崩溃了。**

### 1.2 时间线重建（ART 入口后 31 事件）

```
#459 set_tid_address → #460 faccessat(路径) → #461-468 prctl(PR_SET_VMA)×8
   （给匿名映射命名——libc/ART 初始化）
#469-471 fcntl(0/1/2, F_GETFL)（stdio 初始化）
#472 newfstatat → #473 openat → #474 prctl(PR_GET_DUMPABLE)
#475/476 newfstatat ×2
#477 writev(fd=2, 0 字节!) + #478 socket(AF_UNIX)   ← async_safe 想打日志
#480 prctl(PR_SET_VMA) → #481 prctl(39) → #482 openat → #483 prctl(PR_GET_NAME)
#484 socket(AF_UNIX) → #485 writev(fd=2, 0 字节!)
   ★★ 此间某处：致命信号到达（无 trace——信号停点当时不留痕）★★
#486 prctl(PR_SET_DUMPABLE,1)        ← debuggerd_signal_handler 开场
#487 prctl(PR_SET_PTRACER, ANY) → EPERM（引擎透传 → 外层策略拒绝）
#488 socket(AF_UNIX)（fatal_errno 想报 logd）
#489 writev(fd=2) 55B："libc: failed to set traceable: Operation not permitted"
   → 进程终局（v1.1.3 同点位 EXIT=0；v1.1.4 无 EXIT 行=TA 取日志时未退或刚死）
```

**"Fatal signal N (code…) at PC" 原文**——真正的崩溃自述——正是那三条
**0 字节 writev 之一**（async_safe 先 socket→logd 失败，回落 stderr writev），
但 v1.1.4 的 tee 读出来是 0 字节（iov 全零或读取失败），内容仍没落地。

### 1.3 v1.1.4 遗留的两个悬案（v1.1.5 一并解决）

1. 三条 writev 为什么 0 字节？（iov 原文未留痕 → 无法判读）
2. 崩溃信号到底是几号、PC 在哪？（信号停点静默转发 → 零记录）

## 2. v1.1.5 三件套（全是为下一份日志准备）

| 改动 | 说明 |
|---|---|
| **[sig] 信号停点全记录** | 真信号转发前 GETSIGINFO+GETREGSET：`[sig] t=N 信号 M（code=X addr=Y）pc=Z lr=W sp=V` → 离线 llvm-objdump 按 ROM .symtab 符号化，直指凶手函数 |
| **tee 扩面** | write/writev 全 fd payload；**0 字节 writev 裸 dump iov 数组**（悬案 1 处决）；openat/faccessat/newfstatat **抄路径**（崩溃前最后碰的文件直接见字） |
| **prctl(PR_SET_PTRACER)→0** | 引擎假装成功——语义正解：tracer 就是我们，VM 内"可附身"恒真。修复后 debuggerd handler 不再死在 EPERM，走完 clone 伪线程 → tombstone 流程（即使半路失败也会把信号 re-raise 回来，[sig] 都看得见） |
