# TwinVM v1.1.8 —— abort 因果链闭环：vm_set_exec_path 定义了却从未被调用

> 输入：v1.1.7 真机日志（4687 行）。dumpable 总闸门验证通过，**ART 崩溃的
> 完整原因第一次以原文形式落在日志里**。

## 2. 因果链闭环（v1.1.7 日志 617 行）

```
[tee] fd=2 writev（80 B）: unable to stat either "/proc/self/exe" or "dalvikvm": No such file or directory
[sig] 收到信号 6 … pc=0x723c1f7c1c（__dl_abort）
```

ART 启动时 stat("/proc/self/exe") 失败、再 stat("dalvikvm") 失败 → Fatal。

**根因（一行字）**：`vm_set_exec_path()` 在 vm_core.c 定义、在 /proc/self/exe 的
stat（newfstatat 931 行）与 readlinkat（1001 行）两处特判里使用——
**但全工程没有任何调用点**。`g_exec_path` 恒空 → 特判恒不触发 →
stat("/proc/self/exe") 走 ROM 查找 → ENOENT。

## 3. v1.1.8 两刀

| # | 修复 | 位置 |
|---|---|---|
| 1 | **exec_dyn 装载时 `vm_set_exec_path(execfn)`**（真正的 exec 点设自我路径；stat/readlink 两特判同时复活） | vm_loader.c |
| 2 | **/proc/self/comm 合成**（"dalvikvm\n"）——Fatal signal 报告的线程名不再是 `<name unknown>` | vm_core.c openat |

## 6. 本轮教训（第七类：**写了特判≠接了数据源**）

> /proc/self/exe 的 stat 特判 v0.8.x 就写了，readlinkat 特判更早——但喂它们的
> `vm_set_exec_path` 一直没人调用。**检查清单**：每加一个"全局状态 + 特判"，
> grep 一遍赋值点的调用链——定义而不调用的 API 是僵尸特判，
> 测试全绿掩盖不了它（测试没跑这条路径）。
