# TwinVM v1.1.9 —— 教训五第二击：exec_path 还是设在子进程（父进程自我认知三件套）

> 输入：v1.1.8 真机日志（4704 行）。comm 合成生效了，但返回的是 "guest"——
> 父进程的 g_exec_path 依旧为空。

## 1. v1.1.8 判读

- **comm 合成生效**：Fatal signal 报告从 `<name unknown>` 变成 `(guest)` /
  `pid 16116 (guest)`——/proc/self/comm 路径通了，但内容错了；
- **"unable to stat either /proc/self/exe or dalvikvm" 依旧**（4 条 tee 载荷）；
- 根因：**vm_set_exec_path 放在 exec_dyn 里 = 子进程调用**，而 stat/readlink
  特判跑在**父进程**（ptrace 后端）——fork 内存隔离，父侧 g_exec_path 恒空。
  comm 的 fallback "guest" 正是铁证（`g_exec_path[0]==0 → "guest"`）。
- 同类顺查：`vm_set_exec_cmdline`（/proc/self/cmdline 数据源）ptrace 模式下
  同样无人调用——一并修。

**这是教训五（"初始化还在旧世界"）的第二次踩坑**：v1.1.6 是引擎装配，
这次是 exec 自我认知。纪律升级：**全局状态的 setter，必须核对调用进程**。

## 2. v1.1.9 修复（一处）

父进程 `tvm_tracer_main` 的 `vm_machine_setup` 之后，按与子进程 exec_dyn
**完全一致的判定**（dv && ld && !TVM_LEGACY_TRAP）设置：

```c
vm_set_exec_path("/system/bin/dalvikvm");          /* stat/readlink 特判复活 */
vm_set_exec_cmdline({"dalvikvm","-cp","/rom/hello.dex","Hello"});  /* cmdline 合成复活 */
```

（legacy 回退分支设 "/bin/guest"。）
