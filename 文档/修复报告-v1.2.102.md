# TwinVM v1.2.102 —— 修"点 B 后 A 被停"（B 并发路径 UI 旁路）

> TA 报告（10-22 10:06）：点完 A 再点 B，A 自己停了、表也不走、
> 提示"日志已保存"——像 A 被终结。

## 定罪

`stage0Parallel` 是**秒回**的（fork 后立即返回启动确认）→ 工作线程
立刻走完整收尾链：
```
running[0] = false       ← 停表（A 的 ticker 死）
stopService(RunService)  ← 停前台服务（A 的保活没了！）
mOut.setText(结果)        ← 翻页（A 的实时画面被覆盖）
Toast"日志已保存"          ← 假终点仪式
```
A 其实没死——是 B 的返回链把 A 的 UI 状态机全误杀了。

## 修复（v1.2.102：B 完全旁路 UI 状态机）

- B 不覆盖 mOut（只 append 一行"已请求启动"）
- B 不启 ticker（A 的表原样走）
- B 秒回后**不走任何收尾**（不停服务/不 release 锁/不翻页/不弹 Toast）
- B 的完成提示 = 轻量文件监听（live-b.log 出现 "-pass in" 后 append 一行）

## 验收剧本

```
① 点 容器A → 表走起来、画面持续刷新
② 立刻点 容器B → 只多一行"[容器B] 已请求启动"——A 的表继续走 ✓
③ 等待：A 翻结果页（stress-all-pass）+ [容器B 完成]（world-all-pass）
```
