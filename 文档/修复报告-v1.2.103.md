# TwinVM v1.2.103 —— 闪退根治：fork 后纯 C 通道

> TA 报告（10-23 06:54）：点完 A 再点 B，闪退。

## 定罪：fork + JNI = 禁区

v1.2.101 的 b-runner 在 fork 后的子进程里调 NewStringUTF/stage0——
fork 只继承调用线程，ART 运行时的 GC 锁/JNI 表处于任意中间态，
子进程一碰 Java 堆就崩（v1.2.102 闪退实锤；v1.2.101 跑到 13s 只是运气）。

## 修复（v1.2.103：fork 后只用 POSIX）

```
fork 前：参数全转 C 串（g_c_rom_path/g_c_live_path）+ 管道 fd 备好
fork 后：g_c_out_fd = 管道 fd
        → stage0 的所有输出走 write(fd)（console_to_jstring 的 C 分支）
        → env 相关调用全部被 g_c_out_fd 条件跳过
        → 子进程零 Java 堆接触
```

stage0 双模式化：
- JNI 模式（A 用）：jstring 参数、NewStringUTF 返回——原样
- C 模式（b-runner 用）：NULL jstring + C 全局入参 + write(fd) 输出
