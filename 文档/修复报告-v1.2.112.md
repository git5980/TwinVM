# TwinVM v1.2.112 —— 容器C 类名竞态修复 + tombstone 消音 + 日志自动存档

## 案一：容器C 找不到类（Unable to locate class 'SampleApp'）

16:17 的 live-c.log：重启后缓存命中、ART 起来了，但 dalvikvm 找的是
'SampleApp'（文件名推断）而非 setMainClass 设置的 com.twinvm.sample.Main。

**根因**：类名决策代码在 fork 后的子进程里读跨线程全局 g_main_class
（UI 线程写）——无同步的数据竞争，读到旧值（空）。setDex 同机制却
"工作"纯属运气。**结构修复**：决策挪到 stage0 入口（主进程 dispatch
线程，Thread.start 的 happens-before 保证看见 UI 写入），子进程只读
fork 继承的快照 g_cls_snapshot——无条件正确。

**诊断线**（下轮 live 日志可直接看）：
```
[TwinVM] [cls] 快照：clsname='com.twinvm.sample.Main'
                （g_main_class='com.twinvm.sample.Main' dex='/data/app/SampleApp.apk'）
```

## 案二：25 连"闪退"实为扫雷 tombstone 噪音

16:17 的 crashes zip：全部 SIGSYS/syscall 112 类 tombstone——是
policy probe/sweep 的 fork 实测子进程被 App 策略杀（设计内探测手段），
但 SIGSYS 默认动作触发 debuggerd → Logfox 全收集 → 看着像连环闪退。

**修法**：实测子进程 fork 后 `prctl(PR_SET_DUMPABLE, 0)`——安静死，
tombstone 禁源（App 本体从未受影响）。

## 案三：live 日志自动存档（TA 的"保存到 document 文件夹"）

live 日志每轮 O_TRUNC 重写——有价值日志会被下一轮冲掉。**修法**：
容器到终点（-pass / 槽位退出）自动在 Documents/TwinVM/archive/ 留
带时间戳快照（twinvm-live-c-20261023-HHMMSS.log），UI 显示 📁 已存档。
