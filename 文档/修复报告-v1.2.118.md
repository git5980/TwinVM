# TwinVM v1.2.118 —— M3 开工：Activity 引导模式（Bootstrap 反射拉生命周期）

## M3 路线（无 AMS 的最小 Activity 环境）

```
标准链：zygote → ActivityThread.main → AMS 协商 → onCreate → SF 上屏
我们没有 AMS/SF，但生命周期可以【引导】出来：

M3-a（本版）：
  dalvikvm -cp app.apk:/system/framework/bootstrap.jar
             com.twinvm.m3.Bootstrap <Activity类名>
  Bootstrap（ROM 注入，3.7KB dex）：
    Class.forName(activity)          ← 类装载
    → 无参构造                        ← 实例化
    → 反射 onCreate(null) → onStart → onResume
    → onPause → onStop                ← 完整生命周期
  异常兜底：打印类型+消息+栈顶 3 帧（下一案定罪材料）
```

## 触发方式

- 列表点选建议含 "Activity" 的项（如 DemoApp 的 com.twinvm.demo.MainActivity）
  → setMainClass → 引擎检测含 "Activity" → boot 模式
- -cp 自动追加 :/system/framework/bootstrap.jar；argv 变 Bootstrap + Activity 名

## 预期首验（DemoApp MainActivity）

乐观：M3-ALL-OK（生命周期全绿）
现实（大概率）：M3-NEXT-CASE + 栈顶三帧——Activity 构造/onCreate 依赖
Context/PhoneWindow（要 WindowManager/Binder）→ 第一案会浮出：
可能是 "NullPointerException attach" 或 UnsatisfiedLink（native 绘制）
——这正是 M3-b（Binder 最小应答）的靶子清单来源。
