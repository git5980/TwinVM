# TwinVM v1.2.121 —— M3 首案：argv 位次错误（Bootstrap 被挤掉）

## 案情（23:37 live-c.log，7025 行）

```
✓ boot 模式触发（[cls] 快照 MainActivity；-cp 双路径；bootstrap.jar 找到）
✗ 无任何 M3-Bootstrap 输出（引导类根本没执行）
✗ CNFE: 'com/twinvm/demo/MainActivity'（斜杠串！）
```

## 根因（低级但隐蔽）

dalvikvm 的 argv 位次：`dalvikvm [opts] 主类 [主类参数...]`

```c
gargv_boot[4] = s_act2;   // ← v1.2.118 把 Activity 名填进了【主类位】
```

Bootstrap 被挤掉，dalvikvm 直接拿 Activity 类名当主类找
（ART 内部把 '.' 转成 '/' 形式查找 → CNFE 显示斜杠串——诊断指纹）。

## 修复

```c
gargv_boot = { dalvikvm, -Xverify:none, -cp, 双路径,
               "com.twinvm.m3.Bootstrap",   /* [4] 主类 */
               s_act2, NULL };              /* [5] Bootstrap 的 args[0] */
```

## 诊断指纹归档（下次秒判）

**CNFE 显示斜杠类名 = argv 主类位传了点号类名**（ART 的 DescriptorLookup
把 '.' 替换 '/' 后失败打印）——不是 dex 内容问题。

make test 5/5；APK **271/1.2.121 SIGN_OK**
