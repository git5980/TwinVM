# TwinVM v1.2.122 —— M3 第二案：zip data descriptor（DEFLATE 流式标志）

## 案情（23:58 live-c.log——Bootstrap 登场后的 CNFE）

```
✓ Bootstrap 跑起来了（目标 Activity 行打印 ✓）
✗ Class.forName(MainActivity) → ClassNotFoundException
```

## 解剖（7000 行日志的完整还原）

```
apk 的 zip 解析【全成功】：EOCD@12288 ✓ CD 5 entries ✓
  classes.dex entry：pread 2608B（压缩段）✓
jar 段（Bootstrap）装载成功 ✓（它跑起来了）
但 MainActivity（apk 段）CNFE ✗
```

**根因锁定（对照实验设计）**：

```
apk（aapt 产）：classes.dex flags=0x2（GP bit1 = data descriptor 模式，
                csize 是占位 0）——APK 标准流式写法
jar（d8 产）：  classes.dex flags=0x0（无 descriptor，csize 可信）

ART 的 ZipArchive 对 flag bit1 entry 走流式解压路径
（inflater 串行读 + 期望真实 csize 从 data descriptor 读出）——
在我们的 ROM 只读 fd 语义下，该路径异常 → DexFile 打开失败被
PathClassLoader 吞掉 → 该元素从 DexPathList 消失 → MainActivity CNFE
```

## 修复（对照实验一步到位）

**DemoApp v3**：全 STORED（不压缩、flags=0x0、无 descriptor）重打——
zip 结构最朴素形态，ART 直接 seek+读。

- ROM 预装同步换 v3（135 inode，f1d484d2）
- 宿主可安装（v3 已签名验签 SIGN_OK，一并交付）
