# TwinVM v1.2.127 —— M3 真凶落网：framework 类缺失（ROM 补全）

## 案情（20:46 live-c.log——mCookie 透视后质变）

```
M3-dexfile: loadClass = null        （上一案）
M3-cookie: [J@3daf937                ← 本案：cookie 非空！dex 打开成功
M3-Bootstrap: 异常 = NoClassDefFoundError: Failed resolution of:
              Landroid/app/Activity;   ← 类定义时解析父类失败！
M3 异常类型: ClassNotFoundException: android.app.Activity
  at dalvik.system.DexFile.defineClassNative
```

## 根因（三层透视后终于钉死）

```
MainActivity extends android.app.Activity
  → defineClass 解析父类 Activity
  → BOOTCLASSPATH 里只有 ART 六件套（core-oj/core-libart/…）
  → ROM 的 /system/framework/ 【没有 framework.jar】
  → CNFE android.app.Activity

Stage 0~4.2 的 ROM 只收了 ART 最小面（跑纯 Java 够用）——
Activity 时代的 framework 类从未进过 ROM。
```

## 修复（framework 补全）

- **android.jar（API 34）→ d8 → framework.dex（5.4MB）→ framework.jar**
  注入 ROM /system/framework/（136 inode）
- BOOTCLASSPATH 第 7 件：framework.jar
- 含 Activity/Bundle/Button/TextView/Toast 全 API 面（验证 ✓）

## 边界说明（如实）

android.jar 是【编译 stub】（方法体抛 RuntimeException）——
但 M3-a 的验收目标恰好不受影响：
- 类装载/link 只需【类型存在】✓
- onCreate 是 MainActivity 自己 override 的（不调 super 不触 stub）
- stub 的雷会在 M3-b（真实生命周期调用链）暴露——届时换真机提取件
