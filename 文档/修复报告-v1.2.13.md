# TwinVM v1.2.13 —— 大白话版结案：数格子差一×2，这次先考试再出门

> 输入：v1.2.12 真机日志（6210 行）。判据没出现（stat-fix 仍未触发）。

## 一句话诊断

stat 文件里**第 28 个数字**才是栈地址。我 v1.2.9 数格子少数一格（读成了
第 27 个＝代码结束地址），v1.2.12 声称改回来**又少数了一格**（注释写
"改回 8 个"，代码实际只有 7 个）。第 27 格长得像个地址（0x7ffd769d30）
把我骗了三轮；真正的第 28 格一直是 0。

## 为什么会发生

改 sscanf 格式串时**没有用已知值数据做回归**——%*u 少一个就是读隔壁
字段。v1.2.12 的"修复"和 v1.2.9 的"引入"是同一个动作：手数格子。

## v1.2.13 的做法（教训十五的落实）

1. **先写假数据考试**：构造 stat 文本，第 26/27/28 格填 111111111 /
   222222222 / 333333333；
2. **逐字复制代码里的格式串**进考试程序——读出 333 才允许编译；
3. 考试通过后构建（v1.2.12 的串读出 222，实锤差一还在；修正版读 333）。

修好后链路：解析读到真值 0 → **stat-fix 触发**（从真 maps 取 [stack]
行起点写进第 28 格，token 定位实现早已验证）→ bionic 找到栈。

## 验证

`make -C core test` 5/5 PASS；checkrom PASS；APK 163 SIGN_OK；ROM fa88cc28 ✓。

## 下一轮判据（真机跑 v1.2.13）

```
[stat-telemetry] 解析 startstack=0x0              ← 真值终于显示 0
[stat-fix] startstack=0 → 用 [stack] 起点 0x7ffc… 修补   ← 修复首次触发
"stack not found" 消失
→ Runtime::Init 继续 → Hello TwinVM from ART 🎉
```

## 教训（大白话版）

**改"数格子"的代码，必须先用写满已知数字的假数据考试，考过了才编译。**
以及：守门的（gate）别用诊断的（telemetry）同一双眼睛——万一看错了，
修水管的师傅永远敲不开门。
