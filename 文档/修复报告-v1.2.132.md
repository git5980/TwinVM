# TwinVM v1.2.132 —— M3-b 第一案：attach 模拟（Bootstrap v8）

## 22:03 日志——金子般的定罪材料

真 framework 的 super 链【真的在执行】（非 stub！）：

```
onCreate: Activity.onCreate:1912 读 mActivityInfo.parentActivityName
          → mActivityInfo = null（attach 装的）
onStart:  FragmentController.doLoaderStart() → mFragments = null
onResume: Application.dispatchActivityResumed → mApplication = null
onPause:  synchronized(...) null（mInstrumentation）
onStop:   ActivityTransitionState.onStop → null
```

**五个字段全由 Activity.attach() 装填**——真机上这由 ActivityThread 的
performLaunchActivity 调（反射构造 → attach(12参) → onCreate）。

## 修复（Bootstrap v8：attach 模拟）

```
attachActivity()：
  反射找 Activity.attach(Context, ActivityThread, Instrumentation,
    IBinder, long, Application, Intent, ActivityInfo, CharSequence,
    Activity, String, Configuration)   ← 12 参签名
  组装最小件：
    Context = 动态代理（所有方法返回默认值——不炸 super 链）
    ActivityThread/Instrumentation/Application/Intent/ActivityInfo/
    Configuration = 无参构造实例
  注入 12 参 → 字段全活 → super 链有真路
```
