# TwinVM v1.2.14 —— [stack] 行读时快照 + 保底钳制（大白话版）

> 输入：v1.2.13 真机日志（6150 行）。telemetry 显示 startstack=0x7ffd769d30
> （这次格式考试过了，是真值）且在 abort 后落盘的 [stack] 区间内——
> 一切理论正确，bionic 仍失败。

## 大白话诊断

虚拟机读 stat 拿到栈地址（真值），再去 maps 里找它。我们事后看的 maps
（崩溃后才保存的）里明明有这个地址——但**崩溃处理本身会把栈撑大 8MB**。
也就是说：**guest 读 maps 那一刻的 [stack] 行，可能跟事后看到的不一样**
（那一刻栈还没长到那个地址下面）。以前的验证全拿"事后的照片"对账，
从来没拍过"读那一刻的照片"。

## v1.2.14 做了三件事

| # | 内容 | 目的 |
|---|---|---|
| 1 | **[stack-snap]**：guest 每次打开 maps 时，把那一刻的 [stack] 行拍下来落日志 | 拿到"读时照片"对账 |
| 2 | **[stack-clamp]**：若读时的 [stack] 区间**不含** startstack → 把区间下沿直接改写到 startstack 所在页（文本等长替换） | 保底修复：startstack 按定义就在栈里，改写后必含 |
| 3 | **[stat-mid]** 门闸修复（原来被计数器挡住永不触发）+ stat 中段[120,290)全文落日志 | 万一是解析问题，原文在手 |

## 验证

`make -C core test` 5/5 PASS；checkrom PASS；APK 164 SIGN_OK；ROM fa88cc28 ✓。

## 下一轮判据（真机跑 v1.2.14）

```
[stack-snap] 读时 guest 视角: …（0xXXXX…-0x7ffd76c000 … [stack]）startstack=0x7ffd769d30

（或没出现 clamp＝读时区间本就含，那 [stat-mid] 的原文就是下一步的钥匙）
```
