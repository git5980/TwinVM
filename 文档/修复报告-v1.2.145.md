# TwinVM v1.2.145 —— 桥 v4：逐条容错注册（14:54 案：一条签名炸掉整库）

## 案情

```
M3-bridge: 装载失败 = NoSuchMethodError:
  Landroid/os/SystemProperties;.native_get(Ljava/lang/String;)Ljava/lang/String;
  ← 桥 v2 注册的【单参 native_get】在 TA 的 framework 上不存在
  ← RegisterNatives 整组调用遇错抛异常 → JNI_OnLoad 失败
  ← 整库装载失败——连 Log 桥都没了（一个签名错全连坐）
  ← 后续 HandlerThread 流程炸、guest 静默 92s 被强杀
```

## 修复（桥 v4）

```
RegisterNatives 从【整组一次性】改为【逐条独立】：
  每条单独调 → 失败（该签名不存在）→ ExceptionClear 跳过
  → 库装载永不因单条失败而炸
```

## 工程教训（入库）

JNI 桥的注册必须逐条容错——桥的使命是【兜底】，
自身不能成为新的单点故障。
