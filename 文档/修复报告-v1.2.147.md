# TwinVM v1.2.147 —— Bootstrap 进 boot（hidden API 豁免）

## 08:44 日志的五帧完整定罪

```
M3-Bootstrap: 流程异常 = ExceptionInInitializerError
  at android.os.ZygoteProcess.<init>(ZygoteProcess.java:177)

  ↑ Looper.prepare() → new MessageQueue → 触碰 Process → oplus RefClass NPE
```

（v18 打点工作正常——炸点精确到 Looper.prepare 内部。）

## 根因（推断链）

oplus RefClass（OnePlus 反射加速框架）在容器里 RefConstructor=null——
最可疑机制：**hidden API 拦截**。Android 9+ 对非 SDK 接口的反射拦截按
【调用方 classloader】判定——framework.jar 在 BOOTCLASSPATH（自己人），
但触发链上的 Bootstrap 在 -cp（"第三方"身份）→ getDeclaredConstructor
被灰名单策略拦截 → RefClass 拿不到 → null。

## 修复（双管齐下）

```
BOOTCLASSPATH 第 8 件：/system/framework/bootstrap.jar
  → Bootstrap/MiniContext 成为 boot 类
  → 它们发起的反射豁免 hidden API 拦截
  →（副作用皆正：Class.forName 的 loader 语义统一）
```
