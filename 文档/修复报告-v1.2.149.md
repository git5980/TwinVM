# TwinVM v1.2.149 —— ROM 版本指纹（机制级漏洞：APK 升级不换 filesDir 的 ROM）

## 10:07 日志定罪（诊断三步走）

```
1. 日志无 M3-flow/M3-ref 打点（v18/v19 特征）→ Bootstrap 是旧版
2. 我发的 v148 APK 的 ROM 确认含 v19 代码 ✓
3. → ROM 在 filesDir"持续服役"：
```

**机制级漏洞**：`romPath()` 只在 filesDir/demo.rom【不存在】时才从
assets 落地——**APK 升级后旧 ROM 原地不动**（自愈只查 CRC 完整性，
旧内容 CRC 自洽 → 永不替换）→ TA 装 v146/147/148 跑的都是 v145 的
bootstrap（三轮"修复"原地空转！）

## 修复（版本指纹）

```
落地时写 demo.rom.fp（assets ROM 的 MD5）
每次 romPath()：算 assets 指纹 → 与 fp 不一致 → 删旧 ROM 重新落地
（副作用：运行期装的 APK 会丢——"恢复出厂"语义，引擎升级优先）
```

## 追责声明

v146~148 三版的"没效果"【不是那些修复无效】——是没跑到！
v149 起 TA 的每次升级会真正生效。
