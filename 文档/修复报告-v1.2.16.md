## 二、新卡点（通读还原）

```
close(maps fd) → prctl(PR_SET_VMA 命名区) → socket(AF_UNIX, DGRAM|NONBLOCK|CLOEXEC)
→ futex(0xb40000723b04d984, FUTEX_WAIT|PRIVATE, expected=3, timeout=NULL)
→ 90 秒无输出 → 看门狗强杀
```

通读要点：
- **全日志 0 次 clone**（整个会话从未创建任何线程）——guest 是**单线程**；
- futex 等待地址带 **MTE 标签（0xb400 前缀）＝malloc 堆**上的对象；
- expected=3 ＝ bionic mutex 的 "locked+waiters" 状态——它在等**一个不存在的
  线程**释放锁；
- blackbox 的 PC 符号化＝libc `syscall+0x24`（futex 系统调用点本身）——
  说明等待走的是 bionic 的裸 syscall() 包装路径；
- **7 个 socket 建了、0 次 connect**——AF_UNIX DGRAM|NONBLOCK|CLOEXEC 是
  async_safe/liblog 的特征组合，但 connect 从未发生（被什么挡住了？）。

## 三、v1.2.16（观测补齐，不瞎修）

通读后判断：**等待者身份需要证据而不是猜测**（候选太多：scudo 内部锁 /
GWP-ASan / 某个 lazy-init 的 once / uffd 事件循环……）。hang 和 crash 一直
是两种待遇——崩溃有全套验尸（[sig]/栈扫描/maps），**卡死只有 blackbox 裸
数字**。本轮把 hang 提到同等待遇：

看门狗触发时（tracee 在 futex 里睡，读它随时安全）：
1. **GETREGSET**：pc/lr/sp/x0-x2 落日志；
2. **栈扫描**：真 maps 的 r-xp 段筛 [sp,sp+8K)，打印 模块+文件偏移
   （等待者的调用链直接现形）；
3. **maps 全量落盘**（离线符号化弹药）。
