# TwinVM v1.2.17 —— 体检为什么是空的：主线程不是 tracer（教训五第五击）

> 输入：v1.2.16 真机日志（2018 行）。

## 判读（大白话）

看门狗打了"体检开始"和"体检完毕"两行，**中间的体检报告一张没有**。

原因：我把体检代码（读寄存器/栈扫描/maps）放在了**主线程**（看管道输出的
那个循环）里执行——但 **ptrace 只认示踪线程**（就是当初 fork 出 guest 的
那个线程）。主线程去读 guest 的寄存器，内核直接拒绝，而且我写的 if 失败
分支是静默的，连 maps 落盘都被嵌套在那个 if 里面一起跳过了。

这是"谁在哪个线程干活"这个老毛病的第五次现身（前四次：引擎装配、exec
认知、maps 记账、stat 栈基，全是一个家族：**A 线程写的状态 B 线程读**）。

## v1.2.17 修复

改成"主线程下单、tracer 线程干活"：
1. 看门狗置 `g_hang_probe=1`，等最多 3 秒；
2. tracer 在自己的 waitpid 循环顶部看到标志（guest 睡在 futex 里，
   它的 PTRACE_SYSCALL 会立即返回一个停点，所以很快轮到）——
   在**正确的线程**里做 GETREGSET + 栈扫描 + maps 落盘；
3. GETREGSET 失败也显式打 errno（不再静默）。

## 验证

`make -C core test` 5/5 PASS；checkrom PASS；APK 167 SIGN_OK；ROM fa88cc28 ✓。

## 下一轮判据（真机跑 v1.2.17）

```
[hang] pc=0x… lr=0x… sp=0x… x0-x2=…
[hang] sp+0x… 0x… /apex/com.android.art/lib64/libart.so +0x…   ← ★ 等待者调用链
[hang-maps] …
```
拿到调用链即可本地符号化——等待者身份（scudo 锁/once/Barrier/uffd）一眼
定案，对症动刀。

## 教训（大白话）

**下单的和干活的必须是同一个线程——不然就学主线程这次：留张条子
（标志位），让该干活的线程（tracer）看到条子自己去干。**
