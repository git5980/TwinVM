# TwinVM v1.2.31 —— 假设被证伪（SIGUSR1 不是元凶）+ 上 futex 调用环形留痕

> 输入：v1.2.30 真机日志（830 KB）

## 一、★★★★ 诚实结论：**我上一轮的假设被证伪**

v1.2.30 撤掉了 SIGUSR1 处理函数（怀疑打断 ART 挂起协议）。本轮实测：

```
10s: 138,166
20s: 298,231
30s: 403,343   ← 转为 futex 阻塞
40s~110s: 403,343 冻结（nr=98）
```

**futex 阻塞完全照旧。** → **SIGUSR1 处理函数不是元凶**（或至少不是主因）。

> 记录一次方法论成本：v1.2.28 同时引入"阻塞 waitpid（34 倍提速）"与"SIGUSR1 覆盖"，
> 新阻塞点出现时我优先怀疑了后者 —— 排除掉也是净收益（少一个变量、少一处风险），
> 但**必须明确写下"该假设已被证伪"**，避免后续误以为问题已解决。

**guest 已经在读 `/proc/self/stat`** —— 这正是 ART `Thread::Init` → `InitStackHwm()`
读取 `startstack` 的那一步，说明**阻塞点确实落在 `Thread::Init` 内部**，与调用链一致。
（吞吐仍保持 ~15k/s，v1.2.28 的性能收益未受影响。）

## 三、v1.2.31：把"谁该唤醒它"变成证据

两轮都没有"谁该唤醒"的证据，所以本轮直接**记录 futex 调用本身**：

```c
#define TVM_FUTEX_RING 256
static struct { long op; unsigned long long uaddr, val; } g_futex_ring[TVM_FUTEX_RING];
static volatile int g_futex_idx = 0;

/* 示踪器：每次 nr==98 的 entry 停点入环（只记 3 个字段，开销可忽略） */
if ((long)info.u.entry.nr == 98) { …; g_futex_idx++; }
```

卡死时整表倒出（最近 64 条，时间正序，带 op 名字解码）：

```
[futex-hist] 共记录 N 次 futex 调用，倒出最近 64 条：
[futex-hist]   #1234 WAIT (PRIVATE)  uaddr=0x723b04d984 val=3
[futex-hist]   #1235 WAKE (PRIVATE)  uaddr=0x723b04d984 val=1     ← 有配对？
```

支持解码：`WAIT`=0、`WAKE`=1、`REQUEUE`=3、`CMP_REQUEUE`=4、`WAKE_OP`=5、
`LOCK_PI`=6、`UNLOCK_PI`=7、`TRYLOCK_PI`=8、`WAIT_BITSET`=9、`WAKE_BITSET`=10，
并标注是否带 `FUTEX_PRIVATE_FLAG`(0x80)。

### 三种情形一眼可辨

| 观测 | 结论 | 下一步 |
|---|---|---|
| 只有 **WAIT**、**从无 WAKE** | 等一个不存在的线程 / 唤醒丢失 | 查 ART 为何**一次 `clone` 都没发**（线程从未创建） |
| 同一地址先 **LOCK** 再 **WAIT**、无 **UNLOCK** | **自死锁** | 查我们是否重放/改写了某个 syscall |
| 有 **WAKE** 但 waiters=0 | 唤醒发早了（竞态） | 查时序 / 信号与 futex 的交互 |

## 五、下一轮判据

```
[futex-hist]  #N  WAIT (PRIVATE)  uaddr=0x723b04d984 val=3
[futex-hist]  #N+1 ???            ← ★ 关键：卡死前最后一次 WAIT 之前/之后有没有 WAKE
[futex] uaddr=0x723b04d984 … lockword=0x3(LOCKED=1 WAITERS=1) owner_tid=… → ★
```

**拿到这两个表就能把根因钉死**，并据此选一条修法：

* **自死锁** → 检查我们是否对 `rt_sigprocmask(135)`（**当前在拦截清单里**）
  做了不完整的模拟 —— 这是目前唯一"可能扰动 ART 锁协议"的拦截项，
  下一轮会重点核它的实现；
* **等不存在的线程** → 检查 ART 线程创建路径为何走到不 `clone`；
* **唤醒竞态** → 检查 futex 与信号的交互（v1.2.30 已把 SIGUSR1 覆盖撤掉，
  此变量已消除）。

## 六、累积方法论（本轮）

| 教训 | 体现 |
|---|---|
| **假设被证伪要显式记录** | 否则下一轮会误以为"已修"。本轮明确写下"SIGUSR1 不是元凶" |
| **排除变量也是收益** | 即便不是元凶，撤掉一个自己装的信号处理函数仍是净收益（少一处与 ART 抢信号的风险） |
| **两轮都缺同一类证据 → 直接为它建一张表** | "谁该唤醒"缺两轮 → v1.2.31 上环形留痕，不再靠推断 |
