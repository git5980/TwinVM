
### bionic/libc/bionic/pthread_attr.cpp（已克隆核对）——决定性公式

```c
static int __pthread_attr_getstack_main_thread(void** stack_base, size_t* stack_size) {
  ...
  if (stack_limit.rlim_cur == RLIM_INFINITY) stack_limit.rlim_cur = 8 * 1024 * 1024;
  __find_main_stack_limits(&lo, &hi);        // ① startstack=stat 第28格
  *stack_size = stack_limit.rlim_cur;        //    ② 扫 maps 找包含它的区间 → {lo,hi}
  *stack_base = (void*)(hi - *stack_size);   // ③ base = 区间 hi − RLIMIT_STACK
}
```

### 案情还原（大白话：两本账）

- **账本 A（内核栈）**：maps 的 `[stack]` 行（fork 留下的原生栈 0x7ffcf6d000-0x7ffd76c000）、
  stat 第 28 格 startstack（0x7ffd769d30）——都是真值直读；
- **账本 B（引擎栈）**：guest 主线程**实际跑在** exec_dyn 的 1MB mmap 栈上
  （sp≈0x723be6xxxx）。
- bionic 拿账本 A 报给 ART：base = hi−8MB。ART 的 FindStackTop（真实 sp 方向）
  与 GetStackEnd（账本 A 方向）对不上 → **CHECK 当场翻车**。
- 这是 stat/maps 一致性战役（v1.2.7~15）的**最深一层**：以前修的是"内核账本
  内部自洽"，这次是"内核账本 vs 引擎账本"。

6. **futex uaddr 上下文 dump 64B**（看等待对象全貌）。

## 四、v1.2.36 修复：引擎栈"改账"（三处配套，缺一不可）

1. **vm_loader.c exec_dyn**：栈 1MB→**8MB**（恰使 bionic 公式 base=hi−8MB 落回
   栈 lo，自洽）+ **底部 PROT_NONE 守护页**（mmap 栈没有内核 [stack] 的
   grow-down 保护，深递归会踩邻居）+ **vm_set_exec_stack 登记** {lo, hi, 初始sp}；
2. **maps 合成 [stack] 改账**：删光内核 [stack] 行 → 追加引擎栈行
   `lo-hi rw-p … [stack]`（[stack-exec] 留痕）；
3. **stat 第 28 格 startstack 改账**：改写为引擎栈初始 sp（等宽优先，变长
   memmove 兜底；[stat-exec] 留痕）——与 ② 配套，bionic 才能在 maps 里找到
   包含它的区间。
- 旧 [stack-clamp] 钳制在改账模式下禁用（ss_now 是内核真值会误伤引擎行）；
- 跨进程取数：g_exec_stack 在子进程（exec_dyn）写，父进程 syscall 处理时
  vm_mem_read 跨进程读（fork 无 exec → 同 .so 同地址，教训五第二击同款）。
