# TwinVM v1.2.37 —— ★★★★ 内核 ptrace.c 源码定罪：TRACEME → SEIZE（PTRACE_INTERRUPT 复活）

> 输入：TA 上传的 `linux/kernel/ptrace.c`（GPL 源码，2026-10-17 00:07）
> 方法论：与 bionic/art 同款——**内核侧 ptrace 真源码逐行核对**，不是猜。

## 一、内核源码三处铁证

### 1. PTRACE_INTERRUPT 需要 PT_SEIZED（v1.2.19 EIO 悬案结案）

```c
// kernel/ptrace.c → ptrace_request():
case PTRACE_INTERRUPT:
    if (unlikely(!seized || !lock_task_sighand(child, &flags)))
        break;                     // ← ret 保持 -EIO
```
`seized = child->ptrace & PT_SEIZED`——只有 **PTRACE_SEIZE 附着**才置位。
我们一直用 `PTRACE_TRACEME`（只设 PT_PTRACED）→ INTERRUPT 恒 EIO。
**真机 v1.2.19 的"INTERRUPT 失败 errno=5"不是机型差异，是附着的姿势问题。**

### 2. SEIZE 的时序安全性（两种顺序都合法）

```c
// ptrace_attach()（SEIZE 分支）：
flags = PT_PTRACED | PT_SEIZED | (options << PT_OPT_FLAG_SHIFT);
...
if (task_is_stopped(task) && task_set_jobctl_pending(task, JOBCTL_TRAP_STOP | JOBCTL_TRAPPING)) {
    task->jobctl &= ~JOBCTL_STOPPED;
    signal_wake_up_state(task, __TASK_STOPPED);
}
...
wait_on_bit(&task->jobctl, JOBCTL_TRAPPING_BIT, TASK_KILLABLE);
```
- SEIZE **不主动陷停**（`send_sig_info(SIGSTOP)` 只在 ATTACH 分支）；
- 若子进程已 group-stop，SEIZE 内部把它转成 traced stop（TRAPPING 位等完成）；
- → **先 raise 后 seize / 先 seize 后 raise 都安全**。

### 3. 初始停点必须用 SIGSTOP 而非 SIGTRAP

去掉 TRACEME 后，若子进程 raise(SIGTRAP) 抢在 SEIZE 落地之前：
SIGTRAP 默认动作 = **terminate + core dump**（子进程当场死亡）。
SIGSTOP 默认动作 = 组停（无害，等 SEIZE 收编）。
故子侧改为 `raise(SIGSTOP)`。

### 顺带核对（与既有代码对照）

- `ptrace_check_attach`：除 KILL/INTERRUPT 外所有请求都要求 tracee 处于
  `__TASK_TRACED`——我们 GETREGSET ESRCH 史的全部法理；
- `ptrace_resume`（CONT/SYSCALL）：清 `JOBCTL_TRACED` + `wake_up_state`，
  data=0 吞掉当前信号——现有"新线程 SIGSTOP 吞掉"分支语义不变；
- SEIZE 时 options 一次写入（省掉 SETOPTIONS 一步）。

## 二、v1.2.37 改动（三处）

1. **子进程**：删 `ptrace(PTRACE_TRACEME...)` + `raise(SIGTRAP)` →
   改 `raise(SIGSTOP)`（唯一竞态安全的初始停点）；
2. **父进程握手**：`PTRACE_SETOPTIONS` 两步 → `PTRACE_SEIZE(pid, 0,
   TRACECLONE|TRACESYSGOOD|EXITKILL)` 一步（options 随 SEIZE 写入），
   `waitpid` 后照旧 `PTRACE_SYSCALL(pid,0,0)` 吞 SIGSTOP 续跑；
3. 两处旧注释更新（"INTERRUPT 只支持 SEIZE 附着的 tracee"——补注 v1.2.37
   已 SEIZE，INTERRUPT 复活为备用通道）。

**不改的**：体检主通道仍是 /proc + process_vm_readv（对运行中任务有效、
不打断 guest）——INTERRUPT 只是"停点级寄存器/帧链"需要时的备用武器。
