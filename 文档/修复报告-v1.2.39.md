# TwinVM v1.2.39 —— ★★★ 环境层拒绝 SEIZE 案：回退 TRACEME 主路 + 有界握手（绝不 90 秒死等）

> 输入：v1.2.38 真机双日志（live 228 行 + logcat 导出）——**启动期失败**，与
> v1.2.37 上午的成功运行同代码路径对照判读。

## 一、v1.2.38 真机判读（228 行之死）

**死亡序列**：
```
握手三连 -1（seize=-1 重启=-1 停点信号=-1）
孩子 raise(SIGSTOP) → wchan=do_signal_stop（组停）
  → 没有 tracer 接手 → waitpid（无 WUNTRACED）永远等不到事件
  → 黑匣子 silent 1s..89s（孩子全程 T 态）
  → 90 秒看门狗强杀
```

**与上午成功的对照**（同代码，v1.2.38 唯一改动=syscall 拦截名单，握手代码分毫未动）：

| | v1.2.37 上午 09:22 | v1.2.38 中午 12:07 |
|---|---|---|
| pid | 28936 | **2750（重启后的低 pid）** |
| seccomp(2) 挂起 | 有 | 有（相同） |
| SEIZE | **seize=0** | **seize=-1** |
| 启动段（71-73 行） | 相同 | 相同 |

**结论：环境层（设备重启后的安全状态）拒绝了 parent→child 的 SEIZE 附着**。
内核源码（TA 上传 kernel/ptrace.c）裁定：SEIZE 必须过
`__ptrace_may_access(PTRACE_MODE_ATTACH_REALCREDS)`（受 dumpable/LSM/Yama
摆布，EPERM/EACCES 返回点都在 ptrace_attach 开头）；另 `if (task->ptrace)
→ EPERM`——**已 TRACEME 的孩子不能 SEIZE 升级，两法互斥**。

## 二、v1.2.39 修复（三层）

1. **回退 TRACEME 主路**：子侧 `ptrace(PTRACE_TRACEME)+raise(SIGTRAP)` +
   父侧 `SETOPTIONS+PTRACE_SYSCALL`——**100+ 版本本机全过**（TRACEME 是孩子
   侧自我声明，不吃 parent 侧的 may_access 检查）。SEIZE 的唯一收益是
   PTRACE_INTERRUPT 资格——体检主通道 /proc 不需要它，不值这个险；
2. **有界握手**：waitpid 改 WNOHANG 轮询（≤3s）——任何一步失败快速失败并
   强杀槽位，**绝不留 90 秒死等**；
3. **errno 落日志**：握手行带 errno + 孩子退出码（98=TRACEME 被拒）——
   下次环境层再拦，一眼看出是哪层拦的。

## 三、v1.2.38 的 socket 修复状态

本轮 228 行日志停在握手，**socket/connect 原生化（fd 所有权修复）尚未接受
真机检验**——代码保留在 v1.2.39 中，与本次回退无冲突。
