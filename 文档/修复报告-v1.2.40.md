> 输入：v1.2.39 真机日志（6.1MB / 72404 行）——**判据链全过后的最深一跑**。

## 一、v1.2.39 真机判读（全过）

1. **TRACEME 主路恢复**：`握手(TRACEME): 停点信号=5 waitpid=7196 setoptions=0 重启=0` ✓
2. **socket 原生化生效**：fd=37 成为**活的 logd 通道**——ART 运行时消息全部流出
   （uffd-GC 探测、CMC GC、boot.art image space 回退、`runtime.cc:719] Runtime

3. **栈改账持续工作**（[stack-exec] 多次改账 + [stack-snap] 对账）。

## 二、真凶落网（符号化闭环）

帧链（本轮新写通用符号器，段布局指纹匹配）：
```
#7  JNI_CreateJavaVM+0x104                       ← libart
#3-#6 某库 4 帧（ColorOS abort hook 路径）
#2  liblog+0xC2B4 blr [abort hook] → 0xC2B8 abort@plt  ← 断言函数本体
#1  libbase TEXT+0xF3C8（LogMessage 析构区）
#0  art::Runtime::Abort+0x334 → abort()
```
**sp+0x240 栈上躺着格式化好的断言消息**（74B，与 fd=2 的 LOG(ERROR) 同文）：
```
"Failed to read /system/etc/public.libraries.txt: No such file or directory"
```
即：**libnativeloader 读不到 public.libraries.txt → 先 ALOGE（我们看到了）→
ColorOS 补丁再 LOG_ASSERT 同一条 → FATAL → abort**。AOSP 原版此文件缺失只是
降级，ColorOS 把它改成了硬断言（"Failed to read" 文案 AOSP 有，断言是 OPLUS 加的）。

v1.2.38 的 socket 修复**方向正确但不是这个 abort 的主因**（fd 所有权 bug 真实
存在，socket EBADF 也会炸 logd 路径——两个问题叠在同一条断言链上）。

## 三、v1.2.40 修复

**ROM 追加 `/system/etc/public.libraries.txt`**（306B，只列 ROM /system/lib64
真实存在的 9 个库）——工具 `tools/rom_add.py`（就地追加，逐 inode 原样保留）。

**ROM md5: fa88cc28 → 297c0f8b**（v1.2.40 起以此为准）。

### 事故与恢复（记入教训）
构建时 `build.sh` 发现 `rom/fixture/android_root/system/` 存在（我为放 txt 创建的）
→ 触发重打条件 → **61MB ROM 被打成 2MB 废包**。恢复：从 v1.2.39 APK 提取原 ROM
→ rom_add 重新追加。防护：build.sh 重打条件改为**必须见 lib64**。
