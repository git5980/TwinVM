> 输入：v1.2.42 真机日志（620KB / 6784 行——死得更早，因为 v2 配置还改坏了 default ns）。

## 二、根因（bionic linker_main.cpp 源码判读 + 日志时序）

```cpp
static ExecutableInfo get_executable_info(const char* arg_path) {
  exe_path = "/proc/self/exe";
  stat(exe_path) 成功（我们的 newfstatat 特判）→   // 日志 #479
  result.path = realpath(exe_path, sym_path) ?: exe_path;
  //                          ↑ 失败！             ↑ 所以停留字面
```
**日志实锤**：#479 newfstatat("/proc/self/exe")（成功）→ **#480 openat("/proc/self/exe") → ENOENT**（realpath 的内部 open/lstat 组件）。

realpath 为什么失败？bionic realpath 是**逐组件算法**：
```
lstat("/proc")        → ROM VFS 没有此目录 → ENOENT → 整链失败
```
（哪怕 /proc 能过，后面还有 /proc/self 的 symlink→readlink→/proc/<pid>/exe 一整条链。）

**下游后果链**（三层）：
```
result.path = "/proc/self/exe"（字面）
→ ld.config 的 dir.system=/system/bin/ 段匹配失败
→ config 弃用（no_config 路径，库装载靠内置默认路径所以一切正常！）
→ g_exported_namespaces 恒空 → android_get_exported_namespace 双 NULL
→ libnativebridge "Failed to get system namespace" 断言
```
**这也解释了为什么 v1.2.42 的 visible=true 没用**：配置文件根本没被段匹配选中。
（v1.1.9 修 stat 特判时没暴露本案——因为当时没有 namespace 需求。）

## 三、修复（v1.2.43：/proc 伪文件系统最小目录链）

引擎三处补齐（core/src/vm_core.c）：
1. **newfstatat**：
   - `"/proc"`、`"/proc/<pid>"` → S_IFDIR（realpath 第一跳）
   - `"/proc/self"` → lstat=S_IFLNK(size=len("/proc/<pid>"))，stat(跟随)=S_IFDIR
   - `"/proc/self/exe"`、`"/proc/<pid>/exe"` → lstat=S_IFLNK(size=len(g_exec_path))，
     stat=ROM 真身文件 stat（原语义保留）
2. **readlinkat**：
   - `"/proc/self"` → `"/proc/<pid>"`（新）
   - `"/proc/<pid>/exe"` → g_exec_path（新，realpath 解析完 self 后的形态）
3. **openat**：`"/proc/self/exe"` → **从 ROM 打开真身**（内核语义必须成功；
   v1.2.42 实锤 ENOENT）

realpath 走通后：result.path="/system/bin/dalvikvm" → 段匹配命中 [system] →
visible 生效 → 导出表注册 → 断言解除。
