> 输入：v1.2.44 真机日志（2.5MB / 29515 行）。

## 一、v1.2.44 判读：配置首次完全生效

- ✓ **"couldn't read" 警告消失**（0 次）——ld.config 首次全链生效
  （读入→解析→realpath→段匹配→namespace 建表→visible 导出）；
- ✓ nativeloader 的 preload 真正开跑（fd=37 活 logd 通道：
  `InitDefaultPublicLibraries for_preload=1: ld-android.so:libbinder_ndk:...`）；
- ✗ 断言升级为 TLS 模型案（sp+0x240 解码）：
```
Error preloading public library libbinder_ndk.so: dlopen failed:
 TLS symbol "(null)" in "/system/lib64/libc.so" referenced from
 "/system/lib64/libc.so" using IE access model
```

## 二、根因（源码级三段推理）

1. **谁报的**：linker_relocate.cpp 的 R_GENERIC_TLS_TPREL 处理——
   `mod.static_offset == SIZE_MAX`（该 TLS 模块无静态区偏移）→ DL_ERR。
   static_offset 分配只发生在 `g_static_tls_finished` 置位前（linker_tls.cpp
   的 ensure_init），而置位在 linker_main 的 find_libraries 之后——
   **主程序依赖装载完，静态 TLS 区就封盘**；
2. **谁触发的**：libc.so 里 gwp_asan 的线程局部变量 `_ZZN8gwp_asan15getThreadLocalsEvE6Locals`
   （唯一一条 TPREL64/IE 重定位，指向 .tdata 8B）——**它在 libc 被当新模块
   重装时**才走重定位；
3. **为什么重装**：nativebridge 的双查询（反汇编实锤：0x163d="system" →
   0x1410="default"）——v3 配置把附加 "system" ns 也 visible 了 → **首查命中
   空 ns** → dlopen(libbinder_ndk) 把依赖 libc.so 装进 system ns（不同
   namespace 的 soname 查重不命中）→ libc 第二实例 → 新 TLS 模块 → 封盘后
   无 static_offset → IE 报错。
   **真机 AOSP 的 [system] 段没有 "system" 附加 ns**——首查 nullptr →
   fallback "default"（dalvikvm 启动时全部库已装在里面）→ soinfo 复用 →
   libc 永不重装。

## 三、修复（v1.2.45：ld.config.txt v4）

- **删掉附加 "system" namespace**（首查落空 → fallback default → 复用）；
- default.visible=true 保留（nativebridge + libart OAT 的 GetSystemLinkerNamespace
  双查询的落点，后者同样实测 "system"→"default" 双串）；
- art/sphal/vndk/rs/twrp 附加 ns 保留（art.visible=true 防 OAT 兄弟断言）；
- **ROM md5: 727593aa → b5603f8d**（69 inodes）。

## 四、旁证（本修复的完整性）

ld-android）**IE/TPREL 重定位计数 = 0**——唯一 IE 在 libc；libc 不重装后，
本链 TLS 零雷。
