# TwinVM v1.2.5 —— 修好我自己埋坏的摄像头（栈扫描双 bug）

> 输入：v1.2.4 真机日志（5742 行）。结论先行：**这轮 guest 没有新死法——
> 是我的栈扫描探针自己坏了**（静默无输出）。

## 1. v1.2.4 判读

- `[sig] （Abort message=NULL——裸 abort 无消息…）` 出现 ✓（SI_QUEUE 分支正常）；
- **栈扫描完全没输出**——本该打印"筛 N 个可执行段"的行不存在；
- FP 链照旧垃圾值；maps 全文落盘正常（这部分是流式 live_write，不受影响）。

## 2. 探针双 bug（都在我 v1.2.4 写的代码里）

| # | bug | 后果 |
|---|---|---|
| ① | maps 有 ~350KB，我却用 `acc[2049]` 缓冲，且 read 一把读 4096B——首次 read 就被"装不下"守卫拒收，**缓冲恒空** | 段表 0 条 → `if (nseg>0)` 假 → 整块静默跳过 |
| ② | sscanf 格式错位：`%*s %*s %*s` 把 offset/dev/**inode** 全跳了，再拿 `%llu` 去解析**路径**（必失败返回 3，而我的门槛恰是 `>=3`） | 就算解析了，模块名永远空、偏移恒错 |

**教训十三（observability code 也要自测）**：观测代码自己没有观测者——
它在真机上静默失败时和"没有这个功能"一模一样。本地能造一个最小
自测（写个假 /proc/maps 跑一遍解析）就该做。

## 3. v1.2.5 重写（fgets 流式逐行 + 字段序修正 + 原始栈兜底）

- 正确字段序：`lo-hi perms offset dev inode [path]`（n≥4 且 perms[2]=='x'）；
- 段表 96→256（guest 真实 maps 的可执行段很多：boot-*.oat 一串 + 全部 .so）；
- 每条命中打印 `sp+偏移 地址 模块+文件偏移`（base = lo - foff）；
- **原始栈 hex dump 兜底**（sp..sp+768，96 qword）——就算解析再翻车，
  配合日志尾部 maps 全文也能完全离线符号化，不再空手而归；
- 所有失败分支显式打点（maps 打不开 / nseg=0 / 栈读取失败）。
