# TwinVM v1.2.53 —— ★★★★★ sigtimedwait 案（Signal Catcher 复活）

> 输入：v1.2.52 真机日志（6.5MB / 76424 行）。

## 一、v1.2.52 判读（Runtime 完整形态首次出现）

- ✓ **JIT 双区精确落位**：0x50800000（data 64MB rw）+ 0x52800000（code 32MB
  r-x）+ zygote jit cache 双 32MB——Low4GB 代管生效（候选#0 命中）；
- ✓ **GC 全家桶上线**：HeapTaskDaemon/ReferenceQueue/Finalizer×2/Signal
  Catcher——完整 ART Runtime 的标志；
- ✓ JIT 编译的 main 已在执行（SEGV pc=0x52800858 正是 JIT code cache 内）；
- ✗ 死因链：`nr=137 rt_sigtimedwait → ENOSYS`（Signal Catcher 的 sigwait 通道）
  → "signal_set.h:61] sigwait failed: Operation not permitted" → abort。
  （主线程 JIT 执行 System.out 解引用 null 是 abort 后的次生混乱。）

## 二、定罪

vm_core.c 的 arm64 分支 `case 44: case 43:`（statfs 伪造）**误把 137 也算进
x86 的 statfs 组**——137 在 arm64 是 **rt_sigtimedwait**！Signal Catcher 拿到
假 statfs 数据 → sigwait 语义尽失 → abort。

## 三、修复（v1.2.53 三处）

1. vm_core.c：arm64 分支去掉 case 137（statfs 只留 44/43）；
2. 透传表 + VM_NR_rt_sigtimedwait（arm64=137 / x86=428 对称定义）；
3. gen_bpf.py：ALWAYS 清单 + rt_sigtimedwait（三张 BPF 表同步重生成：
   ALLOW/NOTIF/ALLOW_NRS；_VFS_ARM 移除 137）。

## 四、验证

make test 5/5（含 BPF 一致性自检——本次它当场抓到 x86 侧不对称，补齐后全绿）；
APK **203/1.2.53 SIGN_OK**（ROM 不变 fd02fac4）。

## 五、下一轮判据（真机 v1.2.53）

1. Signal Catcher 挂起等待（正常形态——sigwait 阻塞不是死）；
2. main 完整执行：System.out 初始化 → println → **hello TwinVM from ART** 🎉
