## 一、v1.2.53 判读

- ✓ Runtime 完整形态照旧（GC 全家桶 + JIT 双区 + main 执行）；
- ✗ `nr=137 → 仍 ENOSYS`（"[caller] nr=137 #1" TRAP 打印 + ENOSYS）→
  "signal_set.h:61] sigwait failed" → abort。

## 二、定罪（v1.2.53 的修复只对了一半）

v1.2.53 改了三处但全是 **BPF 路径**（NOTIF/ALLOW 表——seccomp 后端用）。
TA 真机跑的是 **ptrace 后端**（seccomp 被系统封死，v1.2.39 案定论）——
所有 syscall 都进 handler 的 **switch dispatch**，137 没有 case →
default ENOSYS。**BPF 验证**（交付 so 字节码反查）：137 在 ALWAYS 序列
（…131→137→260…）——表是对的，路是错的。

## 三、修复（v1.2.54）

vm_core.c 补 case：
```c
case VM_NR_rt_sigtimedwait:
    return VM_PT4(VM_NR_rt_sigtimedwait, a0, a1, a2, a3);
```
（紧邻 sigprocmask/sigaltstack 的同构透传。）
