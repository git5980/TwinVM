# TwinVM v1.2.56 —— 优雅关机·补刀版（方案二：剧场保安收场）

> 前情：v1.2.55 压力九连测全过 + 三项消音，但 main 返回后
> DestroyJavaVM 的 WaitForRuntimeShutdown 死等 → 槽位挂"运行中"。

## 决策（TA 拍板，三案大白话对比后选定方案二）

- 方案一（dex 加 System.exit）＝ 演员自觉喊散场——只治一个剧本；
- **方案二（引擎识别演完拉闸）＝ 剧场保安看戏单收场——对所有 guest 一劳永逸 ✓**；
- 方案三（改 DestroyJavaVM 等待）＝ 改剧场承重墙——二进制动手术性价比最低。

## 实现（console poll 循环内，三重判据 + 先礼后兵）

判定条件（**三件全齐**才动手，防误杀干活中的 guest）：
1. `len > 0` —— 控制台出过东西（guest 真跑过）；
2. 输出静默 ≥ `VM_EXIT_GRACE_S`(8s) —— 真机实测 ART 收尾 ~3s 静止，8s=2.6 倍裕量；
3. `g_guest_ticks == last_ticks` —— 停点零增长（在挂不在干）。

动作：日志留 `[graceful]` 行 → SIGTERM → 2s 礼让窗 → 仍活则 SIGKILL。

## 验证

make test 5/5；APK **206/1.2.56 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据（真机 v1.2.56）

1. stress 九连测照旧全过（47ms 量级）；
2. **打完最后一行后 ≤10s 内**：日志出现 `[graceful] 输出静默 8s…` → 槽位退出 →
   UI 从"运行中"回到可再跑状态；
3. 无 SIGKILL 兜底（SIGTERM 应已够——若走了兵，日志会显示）。
