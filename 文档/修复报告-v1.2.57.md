# TwinVM v1.2.57 —— 优雅关机 v2（独立时钟修判据失效）

> v1.2.56 真机实锤：压力九连测照旧全过（28ms），但 [graceful] 一条没出。

## 失效定罪（v1.2.56 的坑）

判据 ②（输出静默 8s）**永远无法满足**——v1.2.19 的"活动即前进"逻辑
只要 guest 有任何 ptrace 停点就重置 `last_out`；而 ART 收尾的 Shutdown
线程在 set_tid_address/读 /proc 循环里打转，停点零星不断 →
静默计时被无限刷新（真机日志：stress 后停点又跑了 51 次）。

## v2 判据（独立时钟 + 低频密度）

- `g_last_real_out`：**只在真实控制台输出**时更新的独立时钟（打转不刷新）；
- 停点速率采样：每秒记 `g_guest_ticks` 增量，维护峰值 `peak_rate`；
- 触发条件（三件全齐）：
  1. len > 0（出过东西）；
  2. 真实输出静默 ≥ 8s；
  3. **静默窗口内停点增量 < 峰值速率的 5%**——收尾打转（每秒几十停点）
     vs 正常运行（每秒数千），密度差两个数量级，不会误判。

## 验证

make test 5/5；APK **207/1.2.57 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据

stress-all-pass 后 ~10s 内出现：
```
[graceful] 真实输出静默 8s、停点频率 N/M 峰值 → 优雅关机：SIGTERM→2s→SIGKILL
```
→ 槽位自动退出，UI 回到可再跑状态。
