# TwinVM v1.2.58 —— 优雅关机 v3（观测点错位：管道收不到 stdout）

> v1.2.57 真机实锤：九连测照旧全过（26ms），[graceful] 仍未出。

## 失效定罪（v2 判据本身对了，观测点错了）

v1.2.57 的 `g_last_real_out` 更新点挂在 **console 管道 read**（`pfd[0]`）上。
但架构事实（v1.1.6 决策）：
- guest 的 fd=1 数据 → handler → `vm_console_write` → `vm_console_fd`；
- **父进程把 `vm_console_fd` 改指了 live 文件**（日志直写，绕过管道）；
- 管道里只有 v0.7 时代的旧 guest（/bin/guest 路径）的输出——ART 时代
  **从未有过数据流**。

所以 `g_last_real_out` 恒为 0 → 判据 ② `g_last_real_out > 0` 永假。
（v1.2.56 的"打转刷新"定罪部分正确——两版是叠加病灶。）

## v3 修法（观测点搬到数据真实现场）

`tvm_tee_stdio`（ptrace 后端 tee 现场——日志里每个 `[tee] fd=1` 的源头）：
```c
if ((nr == 64 || nr == 66) && a[0] == 1) {     /* guest 的 stdout write/writev */
    g_last_real_out = time(NULL);              /* 独立时钟在真实现场更新 */
    g_ticks_at_real_out = g_guest_ticks;
}
```

判据②③不变（静默 ≥8s + 停点密度 < 峰值 5%）。
