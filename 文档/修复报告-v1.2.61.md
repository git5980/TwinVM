# TwinVM v1.2.61 —— 优雅关机终章（总闸指向干管道）+ 扫雷缓存路径修复

> 前四轮（v1.2.56/58/59/60）每轮修的都是真 bug 但全部无效——本轮先本地
> 模拟验证再发版（方法修正：不再远程试错）。

## 真根因（本地模拟实锤）

触发判据 ① 是 `len > 0`（console 管道收到过数据）——但 **v1.1.6 为救
ART 日志已把 guest 输出改道直写 live 文件**，管道在 ART 时代恒干涸，
`len` 恒 0 → **总闸恒假**，后四层修复（独立时钟/tee 观测/墙钟采样/
budget 顺序）全被这扇门挡住。

本地三场景模拟（/tmp/grace_sim.c）：
```
旧判据(len>0, 干管道) + 收尾打转30停点/s → 不触发   ← 复现四连败
新判据(去len门)      + 收尾打转30停点/s → ★ 触发（t≈13s）
新判据               + 真干活5000停点/s   → 不触发   ← 不误杀
```

## 修复三件

1. **去 len 总闸**（`g_last_real_out > 0` 已蕴含"出过真输出"）；
2. **[graceful-watch] 自诊断心跳**：真实输出停止后每 2s 打印三项判据值
   （距真输出 Xs / 窗口停点 N / 峰值 M）——下次日志自带答案，不再盲猜；
3. **扫雷缓存路径修复**：v1.2.59 的缓存写 /data/local/tmp——现代 Android
   不许 App 写那里（缓存永远写不进，每启照扫）。改放 live 日志同目录
   （Documents/TwinVM/policy_ok_v211），版本号入名，升级自动重扫。

## 验证

本地模拟三场景通过；make test 5/5；APK **211/1.2.61 SIGN_OK**。
