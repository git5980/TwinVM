# TwinVM v1.2.73 —— 🏁🏁 七版悬案双终章：guest 本来就退出了（ECHILD 无声吞没）+ 主线程 read 半满死锁

> v1.2.72 真机：这次启动快（6s/28 万停点），stress 21ms 后 48 停点+
> 死寂照旧——但这次日志形态（无 ART 长启动）把推理逼到了终点。

## 双终章定罪

### A. guest 从来没死锁——它每次都正常退出了！

stress 后的 48 停点是 ART Shutdown 标准舞步（nr=96 新线程→63 连读→98
futex），最后 exit_group **被 BPF 放行**（放行=原生执行=trace 不打印）→
guest 全员退出 → tracer 的 waitpid 返回 **ECHILD** → 旧代码 **无声 break**。
→ 七版日志的"stress 后死寂"全部是**正常关机**！graceful 永不触发是因为
**根本轮不到它**——guest 自己走完了生命周期。

### B. UI 卡"运行中"的真凶：主线程 read 半满死锁

guest 退出 → wfd 关闭 → 主线程 poll 收 POLLHUP 前最后一次 POLLIN：
read 要求**读满 8KB**，管道里只有 24B（stress 输出）→ **read 永久阻塞**
→ poll 循环卡死 → alive 心跳停（"38s 死亡"之谜）、EOF 收尾不执行、
join 不跑 → UI 永远"运行中"。**经典 poll+read 半满死锁**（poll 只保证
"有数据"，不保证"够读满"）。

## 修复（v1.2.73）

1. tracer：ECHILD/真错误 break 前**打日志**（"guest 已全员退出，示踪终局"）
   + 置 g_t_done 广播终局；
2. 主线程：read 改**小份读**（256B）——绝不阻塞，EOF 正常到达。
