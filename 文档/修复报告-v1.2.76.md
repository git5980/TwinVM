# TwinVM v1.2.76 —— 修"永续新鲜"：间隔判据 → 速率判据

> v1.2.75 真机：吞吐满速 ✓（watch 峰值 39044/s，风暴 6s 走完）——但
> stress 后 watch 止于 4s、graceful 没触发。

## 定罪：guest 的"慢速自检流"永远满足新鲜窗

stress 后 guest 没立刻睡 futex——它在**读自己的 /proc/self/maps**
（日志铁证：stress 后 3 条 stat-mid，fd=10060 转储 maps 内容）。
每秒几十个停点（<300ms 间隔）→ v1.2.75 的"300ms 新鲜窗"被永远满足
→ 慢轮询永不进 → graceful 永不查。

## v1.2.76：判据从"间隔"改成"速率"

```
最近 1s 内停点数 ≥100 → 忙（风暴 39044/s 满速直通，零开销）
<100/s（自检流 24/s、futex 0/s）→ 视为静默 → 20ms 慢轮询驱动 graceful
```
判据只看吞吐，与停点间隔解耦——慢速自检流不再能"续命"。
