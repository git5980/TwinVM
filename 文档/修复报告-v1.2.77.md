# TwinVM v1.2.77 —— close 宽容语义（ART 启动拖 172s+ 的无限循环）

> v1.2.76 真机（TA 点"运行"）：graceful 机制正常（watch 活着、172s 仍在
> 打印）——但 ART 卡在启动早期 3 分钟不前进。

## 定罪：close(虚拟fd) 回 EBADF → guest 重试 → 无限循环

```
停点分布：19.1 万停点里 close(nr=57) 占 9.96 万（一半！）
fd 序列：64 → 10005 → 10060（重复 close 同一 fd）
```

ART init 后期的 close 扫描循环（fd 泄漏防御）扫到**虚拟号段
（≥10000）**：不在 vfs 表里 → `vm_vfs_close` 回 `-EBADF` → guest 判
"没关掉" → 重试 → 无限循环。

**这是 v1.1.3 同款案件的第二幕**（当年真 fd 段 EBADF 重试修了，
这次轮到虚拟号段）。

## 修复（v1.2.77）

`vm_vfs_close` 对**越界号段**和**空槽**一律返回 0（关成功）——
guest 想关的任何 fd 都"关成功了"（语义无害：不在表=本来就没人用）。
