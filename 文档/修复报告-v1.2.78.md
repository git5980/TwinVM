## 定罪：峰值公式的下限陷阱

```
黑盒现场：guest 在 sigaction(6)/getrlimit(7)/sigprocmask —— ART init
        信号准备阶段（健康！47 停点/s，8s 窗口 N=375）
判据：N*20=7500 < 峰值下限*8=8000 → 恰好满足 → 杀 ✗
```

"N*20<峰*8"本意是"频率骤降到 5%"，但峰值下限 1000 让 47/s（4.7%）
的健康慢速也踩线。**ART init 中后段本来就慢（信号准备、类装载都是
低频 syscall），这条公式见慢就杀。**

## v1.2.78：三级判据（tracer 侧 + 主线程侧同步）

```
① 窗口 ≥8 停点/s（8s 窗口 N≥64）→ 活着，不杀（信号准备 47/s ✓ 保护）
② 静默≥8s 且 N<64 → 真死锁（futex 死等）→ 8s 快速收尸
③ 静默≥90s → 兜底（慢速打转永不前进也该收——v1.2.75 读 maps 自检流
   那种 24/s 的真拖延由这条兜住）
```
