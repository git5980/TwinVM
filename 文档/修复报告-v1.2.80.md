# TwinVM v1.2.80 —— 帧回溯段名补全（segnote 覆盖 [anon]）

> v1.2.79 真机：mprotect 直播一条没打——**这本身就是答案**：tvm_virt_nr(226)
> 返回 0（v1.0.1 起 mprotect 明确"不拦截、原生执行"）→ 循环不是我们回填的锅，
> **是 guest 原生在循环**。

## v1.2.79 日志的完整推理链

1. 226 不拦截 ✓（v1.0.1 架构决定：内存原语必须 guest 原生跑）
2. nr-hist：close 76% + mprotect 6% + mmap 7% + prctl —— **混合慢循环**（非单一 syscall 重试）
3. futex-hist 只 2 条 WAKE、**零 WAIT**——guest 没睡，在干活（50/s）
4. 帧回溯抓到了！但所有段都是 [anon]——**map-fill 灌的库段在 /proc/maps 里无名**
5. loop 检测 pc=0x77be34ba8c（mprotect 调用点）——所在库无法定位

## v1.2.80（观测升级，不改语义）

dump_frames 段表构建时：[anon] 段用 **segnote**（v1.2.35 建的 fd→路径登记）
覆盖命名——命中区间即补名。下次帧回溯直接输出：
```
[frames] #01 ra=0x77be34ba8c (去PAC39位) liblog.so +0x1f2a8  段=37KB 可执行
```
而非 "[anon] +0x…"——**循环的庐山真面目（哪个库哪个函数）下轮自明**。
