## 循环的完整解剖（从 ROM 抽库符号化，全部 IN 函数内）

```
mprotect 循环帧链：
  #00 libart.so+0x4ed5bc（__tree_balance_after_insert 区）
  #01 linker64 RX+0xabd78 → soinfo::call_constructors+0x22c  ★
  #02 linker64 RX+0x888f8 → do_dlopen+0x42c                    ★
  #03 linker64 RX+0x81d90 → dlopen_ext+0x50                    ★
  #04 libdl.so+0x34（dlopen PLT 桩）
  #05 libnativehelper.so+0x2400 → JniInvocationInit            ★
  #08 libc.so+0x27b08（fork/上层）
```

**循环 = 反复 dlopen（libartbased.so 等 ART 系库）→ call_constructors →
构造函数内 mprotect**。dalvikvm 的 JniInvocation 在反复 Init。

## 驱动链（blackbox + [fail] + tee 交叉定罪）

```
guest 读 dalvik-cache → ENOENT（隔离生效）
→ userfaultfd → fd=38（真 fd，ioctl 已直通）
→ UFFDIO_API(0xc018aa3f) / UFFDIO_REGISTER(0xc020aa04)
→ mmap(0,0x1000,prot=3,flags=0x22) → **EINVAL**（[fail] nr=222 首次实锤）
→ ART 打印 "MMAP_TRYLOCK is not supported in uffd"
→ 降级重建 heap → 重新 dlopen ART 系库 → 又试 uffd → 又 EINVAL → 永不收敛
```

疑点：该 mmap 参数组合（addr=0, len=0x1000, prot=3, PRIVATE|ANON, fd=32 位
-1 截断形态 0xffffffff）按理内核不该拒——EINVAL 真因待挖。
