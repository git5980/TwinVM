# TwinVM v1.2.82 —— mmap EINVAL 直播补到"首次"路径

> v1.2.81 真机：UFFDIO 直通观测在 ✓（fd=38 req=0xc018aa3f/0xc020aa04），
> 但 [mmap-einval] 没打——**插错了分支**。

## 定位

[fail] 打印有两条路径：
- 老条目命中路径（2189 的 z 循环）——v1.2.81 的直播插在这里；
- **首次路径**（g_nfail++ 新建）——**实际走的是这条**（fail 行是"首次"）。

## v1.2.82

把 [mmap-einval] 直播同样插到首次路径。EINVAL 一出现（mmap(0,0x1000,
prot=3,flags=0x22,fd=?)）即打出六参数 64 位精确形态——fd 的 32 位 -1
截断（0xffffffff vs 0xffffffffffffffff）验证就差这一行。

（v1.2.81 数据已给出部分答案：fail 行 args 里 fd=0xffffffff——
**32 位 -1 已可见**，但还需确认这是 guest 真实传参还是我们读参时
的截断——v1.2.82 的独立直播行给出结论。）

## 验证

make test 5/5；APK **232/1.2.82 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据

```
[mmap-einval] addr=0x0 len=0x1000 prot=0x3 flags=0x22 fd=0x????? off=0x0
→ fd 形态定真因：
   0x00000000ffffffff = 32 位 -1 截断（AArch64 w4 写 -1 清高位）——
     修复=内核/我们侧对 MAP_ANONYMOUS 忽略 fd（或代为规范化为 -1）
   0xffffffffffffffff = guest 真传 -1 → EINVAL 来自别处（继续深挖）
```
