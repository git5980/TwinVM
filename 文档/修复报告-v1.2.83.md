# TwinVM v1.2.83 —— mmap fd 截断修复（EINVAL 终结）

> v1.2.82 真机直播：`fd=0x00000000ffffffff` —— **真因锁定**。

## 全案终审（v1.2.80~83 四版闭环）

```
AArch64 调用惯例：ART 用 w4 写 fd=-1 → 零扩展 → x4=0x00000000ffffffff
→ 内核把 4294967295 当 fd 号检查 → EINVAL
→ ART 判 "MMAP_TRYLOCK is not supported in uffd" → heap 降级重建
→ 重新 dlopen ART 系库 → call_constructors → mprotect 循环
→ 90s 兜底收尸（v1.2.80 帧链符号化 + v1.2.81/82 取证全链定罪）
```

## 修复（v1.2.83：一行寄存器改写）

mmap entry 停点检测 x4 为 32 位 -1 截断形态 → 改写为 64 位 -1 → 放行。
语义等价（MAP_ANONYMOUS 本就无 fd），打日志 `[mmap-fd32]` 限 8 次。

## 验证

make test 5/5；APK **233/1.2.83 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据（uffd heap 复活之战）

```
[mmap-fd32] 第 1 次：x4 0xffffffff → 64 位 -1 规范化
→ mmap 成功 → MMAP_TRYLOCK 提示不再出现
→ uffd heap 建成 → ART 继续深入（新的最远纪录）
```
