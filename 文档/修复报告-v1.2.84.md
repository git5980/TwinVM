# TwinVM v1.2.84 —— userfaultfd 恒拒（uffd-heap 死循环终解）

> v1.2.83 真机：fd 截断规范化生效（4 次 ✓）但循环照旧——EINVAL 只发生
> 1 次（uffd 探测路过），**真正循环是另一件事**。

## 四版全案合拢（v1.2.80~84）

```
guest userfaultfd(282) → 拿到真 uffd fd=38（宿主内核给的）
→ UFFDIO_API/REGISTER 直通成功
→ ART 选中 uffd-heap 模式 → libartbased 构造函数在 heap 区
   反复 mprotect（uffd 接管的页在 VM 里无事件 handler）
→ call_constructors 永不返回 → do_dlopen 悬置
→ 90s 兜底收尸
```

帧链（v1.2.80/83 两版一致）：
`JniInvocationInit → dlopen_ext → do_dlopen → call_constructors+0x22c → mprotect`

## 修复（v1.2.84：掐源头）

**userfaultfd（AArch64 nr=282）恒拒 EPERM**：
- guest 拿不到 uffd → ART 走无 uffd 的普通 heap 路径
  （真机上无数无 uffd 的 App 验证过的老路）
- 引擎 + 拦截表双侧

小插曲：差点把 282 写成 129（x86 的 userfaultfd 号）——AArch64 的 129
是 kill，撞号险些引入 P0 级 bug（教训九续：**syscall 号必须查
arm64/unistd.h，x86 的号不能凭记忆搬**）。
