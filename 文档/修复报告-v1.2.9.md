# TwinVM v1.2.9 —— startstack 之谜的观测+兜底双管

> 输入：v1.2.8 真机日志（6186 行）。真身 stat 读到了（307B）但 startstack
> 仍显示 0，guest 报 "stack not found" 死于 libc abort+0xa0（换算同址）。

## 1. v1.2.8 判读

- 真身直读三连全过：stat 307B、maps 204799B（**53 次 4KB read 全读完**）、
  comm "dalvikvm" ✓；
- 但 bionic 仍报 `stack not found in /proc/self/maps` → abort（pc 符号化
  = libc abort+0xa0，与历轮一致——abort 机器没变，变的是触发者）；
- 落盘 maps 里 **[stack] 区间存在**（7ffcf6d000-7ffd76c000）——maps 侧没问题；
- 矛盾聚焦：**guest 端 startstack 解析结果 = 0**。

## 2. 本机自测揭示的两种可能（一并覆盖）

| 可能 | 证据 | 对策 |
|---|---|---|
| A. 真身 stat 的 startstack 字段就是 0 | **fork-from-thread 的子进程**（kernel 边角行为：start_stack 复制自 mm，但 pthread fork 场景可能为 0） | **[stat-fix]：解析为 0 时，从真身 maps 取 [stack] 行起点，文本替换进 stat 的第 28 字段** |
| B. bionic 的解析比我们的想象挑剔 | 无法排除 | **[stat-telemetry]：把 307B 原文前 120 字符打进 live 日志**——下一轮直接看真数据 |

（自测还抓了一个自己的 bug：token 定位差一——`')'` 后第 25 个 token 是
字段 27（endcode），第 28 字段要数到 26。本机自测 140730620179136 场景
验证通过。）

## 3. v1.2.9 三件

1. **[stat-fix]**：startstack=0 → 读 /proc/pid/maps 找 `[stack]` 行起点 →
   文本替换第 28 字段（token 长度合法替换，数到 26）；
2. **[stat-telemetry]**：stat 原文前 120B + 解析值落日志（下一轮真机
   直接看 kernel 给了什么）；
3. 修正自己的显示 sscanf（真值场景本机验证 140730620179136 ✓）。

## 4. 验证

`make -C core test` 5/5 PASS；checkrom PASS；APK 159 SIGN_OK；
包内 .so 含 stat-telemetry/stat-fix 探锚 ✓；ROM fa88cc28 ✓。

```
[stat-telemetry] 真身 3xxB: 26565 (twinvm-selftest) R …     ← 原文直接可见

```
