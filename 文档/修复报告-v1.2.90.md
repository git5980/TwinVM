# TwinVM v1.2.90 —— 修 v1.2.85 statfs 假结构体越界（踩 libc 金丝雀）

> v1.2.89 真机：**速率修复生效**（吞吐 243/s、ART 全速推进到 statfs 阶段
> ——比以往任何一版都深）——然后 guest abort：
> `stack corruption detected (-fstack-protector)`。

## 定罪（v1.2.85 自己埋的雷）

```
日志铁证：statfs(43)×2 → 紧跟 abort（栈保护金丝雀）
v1.2.85 补漏时写的假结构体：fsid 用了 long[2]（16B）
bionic struct statfs 的 fsid 是 int[2]（8B）
→ 假结构体 128B > guest 栈上真实缓冲 120B
→ process_vm_writev 越界写 8 字节 → 踩 libc 栈帧金丝雀 → abort
```

## 修复（v1.2.90）

- fsid 改 `int[2]`，精确 120 字节
- 加编译期自检：`sizeof != 120` 则跳过写入并留痕（防再踩）

## 验证

make test 5/5；APK **240/1.2.90 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据

```
statfs 两连 → 不再 abort → ART 继续深入
（v1.2.89 已证明：只要不踩雷，启动链是通的）
```
