# TwinVM v1.2.91 —— 低 4GB 强制落位（msync 扫描死循环终结）

> v1.2.90 真机：statfs 雷 ✓ 拆掉（不再 abort）——推进到更深的新一站：
> **msync(nr=227) 196/s 循环扫描低 4GB**，90 秒兜底收尸。

## 定罪（v1.2.20/21 老案重现）

```
观测：msync(0x3a0a9000, 0x1000) 起以 +0xC6000 步进单调扫描
map 观测：hint=0x3a040000 len=0x10000000(256MB) → 内核给 0x76a949e000（高地址）
```

**因果链**：ART 的 `MapInternalArtLow4GBAllocator` 要低 4GB（压缩指针）。
低 4GB 已被 ART 自己的两大块（0x12000000 128MB + 0x1a000000 512MB）+其他
碎片占据，剩余不连续 → 内核"未按 hint"给高地址 → ART 用 msync 逐页探测
区间可用性（映射过的返回 0，洞返回 ENOMEM）→ **永远探不到能放 256MB 的
连续洞** → 死循环。

## 修复（v1.2.91：无需注入的强制落位）

```
mmap exit 侧：发现"hint 在低 4GB 且内核给了高地址" → 置 g_low4_active
mmap entry 侧（下一轮同尺寸）：读 /proc/<pid>/maps 在低 4GB 找真空洞
  → 改写 x0=空洞地址、x3 |= MAP_FIXED → 放行
  → 内核原生成像，guest 拿到精确低 4GB 落点
找不到空洞则留痕放弃（ART 自己换 hint 重试）
```

## 验证

make test 5/5；APK **241/1.2.91 SIGN_OK**（ROM 不变 8d57f5a0）。

## 下轮判据

```

→ ART 拿到低 4GB → msync 扫描停止 → 继续深入
```
