# 热更 v30 —— bridge v5b：JNI_OnLoad 的 pending 异常案（08:32 abort）

## 08:32 日志定罪（裸 abort 的完整链条）

```
runtime.cc:727] Throwing new exception 'no native method
  Landroid/os/SystemProperties;.native_get(Ljava/lang/String;)...'
  with unexpected pending exception: NoClassDefFoundError
→ 裸 abort（signal 6 无消息）——容器死在 Bootstrap 前

真凶：bridge v5 的 FindClass("android/os/BinderInternal") 抛
NoClassDef（guest 的 BOOTCLASSPATH 里没有 framework.jar——
BinderInternal 不在 guest BCP！）→ pending 异常没清 →
后续所有 RegisterNatives 全部带病执行 → SystemProperties
native_get 单参版注册失效 → 调用时 abort。
（v3/v4 没这个坑——它们的 FindClass 全部命中）
```

## 修复（v5b）

```
JNI 铁律补上：每个 FindClass 后 ExceptionCheck → ExceptionClear；
null 类守卫循环里也清。（FindClass 失败合法，挂着不清是罪）
```

## 遗留（M3-c 清单追加）

```
BinderInternal.getContextObject 的注册需要 framework.jar 在
classloader——方案（DexClassLoader 挂 framework 或 BCP 扩容）评估中
```
