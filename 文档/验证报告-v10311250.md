## 3. JNI 注册实测（宿主 JVM）

用 `tools/gen_javastubs.py` 从 ROM dex 生成**完全同签名**的 Java 类/嵌套类，
`System.load(libtvmbridge_host.so)` 触发 `JNI_OnLoad`：

```
$ java -cp build/jni_test/classes RegTest $PWD/build/jni_test/libtvmbridge_host.so
LOADED
[bridge] JNI 注册完成: 437 ok / 0 fail（19 张表）
```

说明：
- 437 = 19 张表全部条目；0 = 没有任何 descriptor 错位/类找不到
- 覆盖 ColorSpace、BaseCanvas、Canvas、Matrix(+ExtraNatives)、Path、Paint、RenderNode
  以及旧有 Log/SP/Trace/SC/Binder/BinderInternal/EventLog/MessageQueue/AssetManager/Typeface
- 该测试同时验证了变参桩 ABI（JVM 按描述符调用，C 侧不读多余参数）

## 4. ROM 工具自校验

对原 ROM 用相同数据执行一次 replace，输出与原文件逐字节一致：

```
$ python3 tools/romtool.py replace /sdcard/Download/demo.rom /system/lib64/libtvmbridge.so work/rom/libtvmbridge.so work/test_same.rom
verify OK: 138 inodes, 181428280 bytes
$ sha256sum /sdcard/Download/demo.rom work/test_same.rom
c43c76b9...  /sdcard/Download/demo.rom
c43c76b9...  work/test_same.rom
```

说明 `tools/romtool.py` 与 `core/src/vm_rom.c` 的 `vm_rom_replace` 语义一致，
可安全用于离线改 ROM / 构建自测 APK。
